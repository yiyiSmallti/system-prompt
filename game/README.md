# System Prompt Unity 工程

这里是游戏本体。3D 校园还在制作，目前做好了：标题画面、陪伴生登记、序章剧情播放（立绘、表情、点击反应、回看）、手机（日程、通讯录、Coop、持有物）、存读档、设置、序章的教学战斗（3D 战场），以及序章里的两段潜空间 3D 探索（缓存海·浅层和深层）。界面全部用 UI Toolkit 在代码里搭，样式在一份 USS 里；潜空间的场景和噪声体由代码用几何体拼出，主角和 DeepSeek 是用 Tripo 生成的人形模型，都配三渲二着色器。没有场景和 Prefab 需要配置。

工程在 Unity 6000.0.85f1（macOS，Apple Silicon）上编译通过，并用[端到端验证](#端到端验证)从标题一路玩到序章结束。

## 打开与运行

1. 用 Unity Hub 打开 `game/` 文件夹，编辑器版本用 `ProjectSettings/ProjectVersion.txt` 里的 6000.0.85f1（Unity 6.0 LTS）。要构建 macOS 播放器还需要装 Mac Build Support 模块。
2. 依赖写在 `Packages/manifest.json`：Input System 1.20.0、uGUI 2.0.0（提供 TextMeshPro，Yarn Spinner 需要）、Yarn Spinner for Unity 3.2.8。Yarn Spinner 从 [OpenUPM](https://openupm.com) 的 scoped registry 下载，打开工程的机器需要能访问 `package.openupm.com`。没有改用 GitHub 的 git 依赖：在 macOS 27 上，Unity 包管理进程调用系统 git 会因 Command Line Tools 只有 arm64 而失败。
3. Player Settings 里 Active Input Handling 已经设为 Input System。代码同时支持新旧两套输入，改成 Both 也可以。
4. 打开 `Assets/SystemPrompt/Scenes/Boot.unity`（一个空场景），直接进入 Play。`GameBootstrap` 会在场景加载后自动创建相机、`GameRoot`、UI 和音频，场景里不需要放任何东西。

第一次导入时字体和立绘较大（三套 Noto Sans SC 各 10 MB），会等一会儿。`Editor/UiAssetImporter.cs` 会给 `Resources/Art` 下的图片关闭 Mipmap、改用高质量压缩，把 BGM 压成 Vorbis。`Editor/ModelAssetImporter.cs` 把 `Resources/Models` 下的 FBX 导入成人形骨骼、动作循环，不导入材质（战斗动作按表只留出手的那一段，原地播放——Tripo 的骨骼把整段位移放在胯骨上、根节点不动，所以按重心取出位移再丢掉，否则动作会带着整段位移往前冲（拍照那条冲出四米）；`Props/` 下的道具导入成不带骨骼和动作的普通网格），并把挂错在四肢上的顶点改绑到躯干（见[还没做的](#还没做的)）。Tripo 给便服 DeepSeek 生成了两条鲸尾，一条从卫衣下垂到脚踝，另一块大尾鳍单独立在脚后、不连身体，侧面看像断成两截；导入时只保留连在身上的部分。Tripo 把每个人的下巴都削得很尖：导入时沿头部中线往下找到下巴（脸的正面一步退回脖子的地方），把嘴以下的脸往上收、下颌稍微放宽，下巴短一点、圆一点。它也校正基础色贴图：Tripo 把亮部压暗，白色、灰色和皮肤提亮回去，有颜色的部分不提亮（否则 DeepSeek 的藏青头发会变成发白的浅蓝）；蓝色整体偏青约 12°，转回设定图的靛蓝，发梢补回饱和度。

潜空间里的人物有表情：会眨眼，说话时嘴巴开合；剧本的 `#face:` 标签（smile、pout、scared、sleepy、concerned）换成对应的眼睛、嘴和脸红；战斗里挨打时皱眉，倒下时闭眼，赢了会笑。Tripo 的模型没有表情骨骼和形变，表情是画上去的。编辑器菜单 **System Prompt → 采集角色正脸**（`Editor/FaceCapture.cs`）从正面拍下每个模型待机第一帧的脸，包括颜色和深度。`Tools/face_expressions.py` 在照片上画出 3×3 的表情图集（闭眼、笑眼、半闭眼、小瞳孔，笑、张嘴、撅嘴、o 形嘴，脸红），存成 `Resources/Models/Characters/<模型>_Faces.png`，眼睛和嘴的位置记在 `Tools/FaceArt/landmarks.json`。三渲二着色器把图集从正面投回脸上，跟着头部骨骼走，只画在和拍摄时一样深的脸面上，所以挡在眼前的刘海照样挡着。换了模型要重新采集、重跑脚本（需要 Pillow 和 numpy）。

主角四套模型的眼睛是重画的。Tripo 依据的设定图里脸只有约 60 像素宽、刘海压到眼睛上沿，生成的眼睛发灰发虚、画着发丝，女主角家居服有一只没有瞳孔，战斗服眼皮上一片白斑。`Tools/face_eyes.py` 在正脸照片上按 `landmarks.json` 的位置重画眼睛（虹膜按设定用深灰，战斗服用青绿）和周围的皮肤，再经采集时一并写出的三角形（`Tools/FaceArt/<模型>_mesh.bin`）贴回基础色，只画在脸自己的表面上，挡在眼前的发丝保持原样；结果存成和基础色一样大、只在重画处不透明的 `<模型>_Eyes.png`，导入时 `ModelAssetImporter` 把它叠在校色后的基础色上，原贴图不改。改眼睛的顺序：跑 `face_eyes.py`，重新采集（贴图会自动重新导入），再跑 `face_expressions.py`。贴图上一只眼睛只有 30 到 50 个纹素宽，再细的笔画会糊掉。

DeepSeek 的战斗服不是 Tripo 绑的骨：模型在 Blender 里绑了 Mixamo 骨骼，加 6 节尾骨，权重按部位修过，所以 `ModelAssetImporter` 不给它改绑，也不修下巴。它的文件里没有待机动作，用的是原来 Tripo 版的待机 `Motions/IdleDeepSeek.anim`。它的头骨在脖子顶端，比 Tripo 的低，所以 `SeaFigure.DeepSeek` 把脸框多往上抬一些。所有动作都是给没有尾巴的骨架做的，会让尾巴跟着胯部整条抬起来：跑步时本该贴地的部分离地最多 24 cm。`SeaFigure` 在每帧摆好姿势之后把尾巴放回地上：前两节跟着胯部，后面每节保持静止时的离地高度；朝向用静止时的方向，只跟着胯部左右转，不跟着前倾；再从上一帧的位置慢慢回正。这样跑动和转身时尾巴拖在身后，尾鳍平铺在地上，跑步和斩击、施法、受击、欢呼时贴地部分离地都在 1 cm 以内。

两张地图都分成几个区域，每个区域的海床颜色、墙和摆设不同，第一次进入时屏幕左侧打出区域名，有的区域 DeepSeek 会说一两句。浅层：气泡礁（起点）、主航道（沉在海底的巨大手机）、表情包珊瑚林、删帖墓地、灯塔背面、机柜峡谷、维护间、灯塔广场；从起点就能看见灯塔和两道防火墙，要绕灯塔一圈到维护终端，再穿过打开的防火墙回来。深层：裂缝、沉没机房，然后西边的回收站（近，有信标）和东边的长上下文回廊（远，有延时补丁）二选一，最后是白门大厅。矮墙挡路但不挡视线，也挡不住光。机柜墙有立柱、顶檐和踢脚，柜里分服务器、硬盘架、配线架、通风格和空挡板，柜顶有转动的风扇；柜门的缝、托盘、把手、通风格和立柱的凹槽按法线打光，有真实的凹凸和高光，主角身上的光会在近处的柜面上照出一圈亮面；海床铺成一米见方的地板，偶尔有透出冷光的通风孔，墙脚一圈接触阴影把墙压在地上，地砖的倒角在主角的光里反光；通道一侧的墙脚散着硬件碎块、发光的数据碎片和从踢脚进出的线缆。走廊里还有 Tripo 生成的残骸（`Dungeon/SeaModels.cs`），按区域挑：死胡同尽头塞着倒下的机柜或线缆盘，拐角立着线缆盘、数据晶簇、电路板珊瑚或旧显示器，墙边躺着倒下的机柜、线缆堆或硬盘堆。残骸挡脚，不挡走廊中线，脚下有一圈区域颜色的光；离道具、机关、噪声体和巡逻点太近的格子不放。

噪声体在地图上巡逻，碰上就进入回合制战斗：走近按 Enter 攻击，没被发现时是先制攻击，背对着被追上的噪声体撞上是被偷袭。打倒的噪声体从地图上消失，信标回满 HP 和 SP，战斗失败回到标题。信标是一座小灯塔：八角塔身绕着几道光带，玻璃灯室里一盏灯，两道光从灯里扫着转，屋顶上立起一根光柱，地上一圈圈光往外扩；休息过后变成绿色。标题党型是一团红黄闪烁的像素方块，不时有方块跳出来，底下往下掉像素，身边接连弹出「震惊！」「点击领取」之类的广告窗；转发型是长满分叉箭头的球，箭头轮流往外一顶，不断复制出往两边飘散的残影。噪声体的眼睛表明状态：打盹时闭着、头上冒 Z，起疑时睁大，追赶时变红、斜成怒眼。人物和噪声体脚下都有一团接地阴影。觉醒前主角一个人用截图战斗，DeepSeek 在灯塔入队后两人一起打。DeepSeek 觉醒前穿周末便服（卫衣裙），在灯塔觉醒后换成战斗服。

战斗在一块 3D 战场上打（`Dungeon/BattleStage.cs`，有自己的相机，界面叠在上面）：队伍站在近处，噪声体在对面，名牌和 HP 钉在各自的噪声体头上。镜头参照《女神异闻录5》的战斗运镜：机位压低，让噪声体显得高大；出事时画面歪斜，点名一个目标用长焦，近身出手用贴地广角；移动快起慢停，停下后像手持一样微微晃动，命中时视野猛地一收再弹开。开场先从噪声体脚下仰拍推近，再甩到队伍身后；以队员为主体的机位都按屏幕位置构图（`BattleStage.Over` 算出绕到多大角度能让队员和目标分在画面两边，`Aim` 算出往哪看能让队员落在指定的屏幕位置，连画面歪斜一起算进去）：队员不进左侧的指令菜单，也不被底部的队伍卡片盖住。选指令时在当前队员右肩后，队员站在指令菜单右边，噪声体在画面右半边，其他队员出画；选目标时推近到队员右肩后两米半，队员的背影在画面左边，目标在右边被长焦拉近；DeepSeek 冲刺斩时镜头趴在跑道旁的地上（回旋扫换到另一边；鱼跃连击先在她右肩后上方看她翻出去；跃劈从海床上仰拍，落地时推近）；主角截图时镜头在主角身后偏右、略高于眼睛，背影和举起的手机在左边，目标在前方（伸臂拍时更高更远，跪拍时贴着海床往上看）；施法和扔道具时在队员外侧低处，队员抬到卡片上方；防御、道具和深度思考时在队员外侧身后偏高处，从肩后看全身姿势，队员偏向场地中间那侧、站在卡片上方（道具和深度思考再往侧面转到 60°，让举到脸边的饭团和按着太阳穴的手从头发旁边露出来）；噪声体单挑一人时镜头躲到那名队员靠外一侧的肩后（中间没有别的队员挡着），退开三米多，队员和噪声体分在画面两边，噪声体朝镜头扑来，打全体时从它侧前方低处拍；全员倒地时在倒地的噪声体旁低处慢慢绕圈，集成时拉远（起手的闪白里队员先离场，镜头前不留人）；ONE MORE 时视野一收；胜利时升到队伍身后高处，看着清空的战场慢慢绕，绕得很慢，结算停多久都还在背后。镜头不靠近人物两米以内，也不转到正面拍脸：Tripo 生成的模型经不起近看，脸只在队伍卡片、技能切入和立绘里用 2D 图出现。进入战斗后队员换成各自的战斗待机（`Resources/Models/Motions/Stance*.anim`）：先用图像模型画三视图姿势参考（`assets/characters/stances/`），再在编辑器里照着图用人形骨骼的肌肉值摆出来（`Editor/StancePoser.cs`，自动把双脚放平踩地，一呼一吸两个关键帧循环）。主角是拿手机迎战的普通学生：男主角双脚大开、膝盖微屈、左肩朝前，左手护在胸前，右手把手机握在腰侧；女主角的不是摆出来的，用的是 Quaternius 通用动作库（Universal Animation Library，CC0，免费的 Standard 版）里的 `Spell_Simple_Idle_Loop`：左手张开伸向敌人，右手垂在腰侧握着手机，带呼吸和重心晃动。动作库按男性体型做，直接套在她身上双脚会开到近两倍肩宽，所以两条大腿的 In-Out 肌肉统一内收 0.12，右手手指按男主角的握法弯成拳（`StancePoser.MakePlayerFemale`，原动作放在 `Editor/Motions/`，生成 `StancePlayerFemale.anim`）；DeepSeek 是冰系施法者：压低重心，右手张开伸向敌人，左手收在胸前。这两条动作没有脚部 IK 目标，所以 `SeaFigure` 播所有动作都不开 foot IK，否则动作淡入时双脚会被拉向身体。防御、道具和深度思考也是照姿势图摆的原地动作（`Guard*`、`Item*`、`Think*.anim`，`StancePoser.MakeAction`，`SeaFigure.Act` 播一次）：从战斗待机的第一帧起势摆进姿势，保持一口气（中途吸一次气），再收回待机。主角防御时压低身体、左肩朝前，左前臂横在脸前，握手机的右拳护在胸口；DeepSeek 防御时右脚在前、身体后仰，双手平推出去、掌心朝敌，像撑着一面冰盾。道具（白米饭）画成饭团：主角左手把饭团高举过头、仰头看着它，右手照旧握着手机；DeepSeek 并拢双膝、耸起肩膀，双手捧着饭团凑到嘴边笑。饭团用掉时一闪消失，受益的队员脚下亮起绿环（`SeaFigure.HoldRiceBall`）。DeepSeek 深度思考时闭眼低头、头歪向右边，右手两指按着太阳穴，左臂横在腹前托着右肘，脚下扩开两圈冷光，「嗯……」「等等」「所以」之类的思考字样绕着头转着往上飘。女主角用男主角的防御和道具姿势，所以会从侧身的施法待机转过来。动作的根旋转和位置要和待机一样烘焙进姿势，否则会被当成根运动丢掉，身体停在待机的朝向和高度上。`-stancePreview` 会把每条动作的保持姿势画成三视图，和参考图对照，并把整条动作拍成 9 帧胶片。出手各有动作，特效是战场上的 3D 物体（`Dungeon/BattleEffects.cs`，每个技能和攻击的设计见 [design/skills.md](../design/skills.md#战斗特效)）：主角站在原地把手机从右手里举起拍照，三种拍法轮流用（`BattleStage.Shoot`）：双手端到脸前；右臂伸直把手机举到臂长、侧着拍；单膝跪地（动作库的 `Fixing_Kneeling` 截前 2.2 秒，`Kneel.anim`），双手把手机放低往上仰拍。都是在底下的动作上把胸口转正，手臂用 IK 弯到手机上（`SeaFigure.RaisePhone`），快门时手边和目标同时闪光，一个绿色取景框收紧在目标上，再连同打下来的像素块一起飞回手机，画面中央弹出这一张截图的缩略图、再缩到左下角（战场相机在快门那一刻从手机的位置、按手机的朝向另拍一张，`BattleStage.Photo`，侧着拍的照片是歪的）；DeepSeek 的饭勺有四套出手轮流用（`BattleStage.Dash`），每场战斗接着上一场的顺序往下，右手里冒出一把木饭勺（`SeaFigure.Wield`），勺头拖一道光带：横斩是拖着水光冲到目标跟前挥刀（Tripo 的斩击），三道刀光（深蓝的一道反着划）；回旋扫从另一侧冲上去，单脚转身贴地扫一圈（动作库的 `Sword_Attack`），刀光贴着噪声体脚下划，海床上扩开水环；鱼跃连击是贴地鱼跃翻滚过去（`Roll`），起身左右两拳（`Punch_Jab`、`Punch_Cross`），先一小下水花，再两道交叉的短刀光；跃劈是蹲身跳起（`Jump_Start`），划一道弧线落到目标面前（`Jump_Land`），刀光竖着劈下，海床上冲起水柱、扩开两圈水环。每套都带水花、火花和冲击环，镜头震一下。接连播的动作（翻滚接左拳接右拳）之间交叉过渡 0.12 秒，不跳帧（`SeaFigure.Play`）。寒流和深海潜流照 PV 的 S15、S16 演：寒流是抬手施法后，掌心放出一股夹着冰晶的寒流横穿画面，几缕光绕着最亮的头部盘旋收拢，镜头在外侧跟着横移，目标瞬间冻进一块透明的冰（`Resources/Shaders/Ice.shader`，带晶簇的多面体），停一下后碎成冰片；深海潜流在敌阵下展开冰蓝漩涡，地上的光臂和往上卷的水柱越转越快，冰晶和气泡被卷上去，噪声体被卷离地面跟着转，镜头快速后拉，最后漩涡爆开，全体冻住、依次碎裂、落回原位。深度思考蓄的力留在她脚下，是一圈慢慢转的刻度光阵和不断上升的光点，下一个技能放出时散掉；防御时队员面前立起一面弧形的六边形光盾，挨打时闪亮，到自己下一回合撤掉。冰镇汽水和辣条是扔出去的：汽水罐翻滚着划出抛物线、拖着气泡，砸中时喷出泡沫、冷雾，地上冒出冰刺；辣条着着火飞过去，炸成火球。打中弱点或暴击时，目标处放射出光线和大冲击环，颜色按属性（冰蓝、火橙），暴击再交叉两道刀光。挨打的队员上半身往后一仰、后退半步：动作库的 `Hit_Chest` 和 `Hit_Head` 轮流用，只作用在腰部以上，双腿保持战斗架势，用到四分之三的幅度（`SeaFigure.Flinch`，动画图里单独一层，带上半身遮罩）；噪声体后仰、倒地或消失。噪声体出手也各有特效：标题党型的「震惊！」扑上来，把写着「震惊！」「点击领取」的弹窗广告一个个砸到队员身上，碎成像素；转发型的「转发保平安」时镜头退到更低、更广的全景，给半空留出地方，它射出三支分叉箭头，升到空中各分裂成三支落向全队。集成也在战场上演：三人轮流拖着光带横穿敌阵斩过，全屏闪白，一头光做的鲸鱼（Tripo 模型，全息着色器）从海底跃过战场，经过时敌人脚下冲起光柱、一起受伤。胜利时站着的队员欢呼。

战斗界面：右下是队伍卡片，头像从卡片上缘探出、略歪，都是 2D 图：主角按性别用家居服半身像（`Resources/Art/Portraits/player_male.png`、`player_female.png`，原图在 `assets/characters/protagonist-card/`，只在战斗卡片和结算里出现，剧情不显示主角的脸），DeepSeek 用战斗服立绘。头像会演表情（`UI/Battle/BattleViews.cs` 的 `CardFace`）：出手时（普通攻击、技能、集成）皱眉、瞪眼、吸气、咬牙蓄力，喊出来并往前一冲、再喊一遍，喘口气，冷笑一下再平静下来；挨打时一愣、闪红，缩起来痛叫、被打歪，疼劲过去后先睁一只眼再睁两只，喘口气瞪回去再吐口气；胜利时在结算盖住卡片前先松口气、睁眼笑出来，结算栏里的头像接着循环哈哈大笑、得意、眨眼、挤眼和咧嘴笑。每种表情 12 张手绘，都是拿原立绘让图像模型只改表情重画的，和原图逐像素对齐；相邻两张渐变过去的地方，再用 ffmpeg 的运动补偿插帧（`minterpolate`）补 2 张过渡帧，只有挨打的那一下直接切。帧按头像窗口裁出（立绘上 554 像素见方，比窗口宽三成，抖动和前冲不露边），铺上卡片底色存成 384 像素的 JPG（`Resources/Art/Portraits/Card/`，每人 37 张原画加 88 张过渡帧，过渡帧命名为 `<起>-<止>-1`、`-2`）。换帧之外，头像全程跟着动作动：攻击时发抖、往前冲，挨打时被打歪、回弹、泛红，胜利时上下晃、左右摆、跳一下。GIF 预览在 [assets/characters/battle-faces/](../assets/characters/battle-faces/)。名字贴在白纸条上，HP 和 SP 是大号数字加血条，HP 降到三成以下变红。轮到谁行动，谁的卡片就上浮、描绿边、挂「行动中」标签。左侧的指令菜单逐行向右错开，每项右边有英文小标（ATTACK、SKILL、THINK、GUARD、ITEM），底下有按键提示。技能和道具列表在指令菜单原来的位置打开，不挡住站在它右边的当前队员。噪声体头上的名牌收窄了，被瞄准时翻成白底并略放大。

战斗规则（`UI/Battle/BattleScreen.cs`）：标题党型头上的「弱点：火」是假的，每场战斗第二回合碎掉露出真弱点；在那之前用冰打中它也会当场揭穿。打中过弱点或耐性，名牌上就记下（「弱点：冰　耐性：火」），之后选目标时名牌上方斜着贴出 WEAK、RESIST 或 BLOCK，没摸清的属性不提示。冰镇汽水和辣条是攻击道具，扔向一个敌人，冰或火属性，威力 30，同样能打出弱点和 One More。转发型不在教学战斗里时，会隔一回合把一只标题党型「转发到十个群」叫进战场（光从它身上射到空位，炸开像素长出来），一场最多叫两只、场上最多三只；叫来的标题党型 HP 16，打倒加 10 EXP。每个队员记得上次打的目标，下次选目标时光标先停在它身上。

深层出口旁的白门在剧情里会变成镜子（`Dungeon/SeaMirror.cs`）：一台反射相机从镜面的另一侧拍场景，镜子里的主角换成还没觉醒的战斗形态（5-battle），一闪之后恢复原样。

两张地图各有一个机关。浅层维护间：站在缓存块后面按 Enter 往前推一格，两块都推进插槽后，橘色的门打开，门后是维护终端；推进死角时按复位台。缓存块是一人高的方块，深色外壳、浅色框架、发光的角，四面是存储单元面板，浮在自己的光上，推的时候先往后一仰，停下时晃一下；插槽是一块深色底座，橘色的边框和朝里的箭头，上面立着一个缓存块的线框，有扫描线往上走，推进去后线框消失，底座、边框和块一起变绿。深层白门大厅：灯塔的光从裂缝照进大厅，四块反射板每按一次转 45 度，把光引到门边的空地上，出口才出现。反射板是叉架上的一面深色玻璃镜，镜面有流动的反光，底座上的刻度盘指明转向；光柱从高处落到裂缝里的棱镜上，光束有白色的芯和顺着光走的条纹，照到的反射板变亮、在落点闪光。小地图上画着插槽、缓存块、反射板和光路。两个机关都能反悔：按 Backspace（手柄 B）撤回上一次推动，或把身边的反射板逆时针转回 45 度；缓存块推进两面墙夹住的角落、再也推不出来时变成红色，DeepSeek 提醒去按复位台。

两张地图各藏着五颗数据珍珠（`Dungeon/SeaPearl.cs`）：海床上一只张开的扇贝，里面浮着一颗发光的珍珠，头上一道细光柱，远处就能看见。走过去自动捡起，全队 SP +5，左上角区域名下显示「◆ 数据珍珠 n/5」，小地图上标粉点；捡齐一张地图有奖励（浅层冰镇汽水 ×2、200 token，深层辣条 ×2、300 token），手机的资料页记着总数。深层的五颗都在两条路共用的区域，走哪条路都捡得齐。

门打开、出口出现、维护进度到 80%、第一次被偷袭这类消息由 DeepSeek 在右上角播报，像《女神异闻录5》的领航员（`UI/Dungeon/NavCall.cs`）：小地图左边甩进一个歪斜的头像框和对话气泡。头像框里是导航专用的半身立绘（`Resources/Art/Portraits/deepseek_nav_*`，从 [assets/characters/deepseek-nav/](../assets/characters/deepseek-nav/) 的原图裁出头肩和手），她手拢在嘴边朝左喊话；便服（浅层）和战斗服（深层，觉醒之后）各有笑、平静、惊慌、嘟嘴四种表情，跟着台词的 `#face` 换，没标的沿用上一句。台词打完停一会儿换下一句，说完滑出去；玩家照常走动，场景里的 DeepSeek 跟着动嘴。对话框出现或进入战斗时播报先让开，结束后接着说。

剧情画面右上角是一排 P5 风格的图标徽章（自动、快进、回看、存档、读档、手机、设置、隐藏界面、菜单），独立于对话框，可以直接点。徽章歪斜错落，角上贴着对应按键（Q、F、L、Tab、H、Esc）；鼠标停在上面时徽章放大、图标变绿，下方弹出名称；自动和快进开启时徽章亮成绿色，手机有未读时变红。日程期限卡在图标下面。标题画面和手机资料页的立绘可以点头和身体，连点太多次会有专门的反应。标题画面上，三个人的视线会跟着鼠标走。标题上的对话气泡浮在所有立绘之上、三人头顶之间的天空处，尾巴指向说话的人；同一时间只有一个人说话，点了另一个人，前一个人的气泡收起、表情复原。

标题的游戏名是单行字标：白色 SYSTEM，后面是歪贴在绿色色块上的黑字 PROMPT，末尾一个闪烁的终端下划线光标。开场时 SYSTEM 从左滑入，PROMPT 色块随着重音砸下来。

## 端到端验证

```bash
game/Tools/e2e.sh
```

脚本先用 batchmode 构建一个测试版播放器，再启动它。测试版产品名是 System Prompt E2E，存档和设置与正式版分开，每次都从空存档开始。启动后，`Assets/SystemPrompt/E2E/PrologueRun.cs` 用虚拟键盘从标题玩到序章结束，沿途经过：

- 标题画面、立绘动态特写、依次点三人的头（核对只剩一个气泡），以及设置
- 陪伴生登记和序章剧情
- 手机、暂停菜单（从菜单进回看、进存档）、回看和快速存档
- 缓存海·浅层探索（DeepSeek 穿便服跟在身边）：从背后攻击礁石出口发呆的噪声体（先制攻击，第一场单人战斗）、点亮信标、珊瑚林、墓地和峡谷各打一场、读墓地的草稿碎片、捡浅层五颗数据珍珠（核对奖励）、第三场战斗扔冰镇汽水打标题党型（核对选目标时不显示没摸清的属性、揭穿假弱点）、最后一场转发型叫来标题党型、在维护间推 11 次缓存块打开门（中途按 Backspace 撤回一次再推回去，核对插槽全满，DeepSeek 在右上角播报「门开了！」时仍在探索）、接入终端解除防火墙、穿过两道防火墙走到灯塔，核对战斗场数和走过的区域数
- 教学战斗（核对 3D 战场和钉在噪声体上的名牌）和 Coop 卡片
- 缓存海·深层探索：从背后攻击发呆的噪声体（先制攻击）、走东边的长上下文回廊读碎片、开宝箱（延时补丁让维护进度下降）、捡深层第一颗珍珠、在白门大厅转动四块反射板把光引到出口（最后一块按 Backspace 逆时针转一次，核对出口出现，右上角播报「出口出现了！」）、走到出口（白门变成镜子，截图镜中的战斗形态）
- 回到标题后打开读档
- 在标题上直接播一次战斗失败的转场（流程里不会输）；再把关机转场完整播一次、中途按确定播一次，核对按确定后用时明显缩短（机器忙时帧率会掉，所以和同一时刻的完整用时比）

运行期间真实鼠标会被屏蔽，只用虚拟键盘操作，免得桌面上停在窗口里的鼠标悬停改掉选中项。潜空间里按最短路径逐格按住移动键，遇到巡逻就转身攻击，战斗里一直按 Enter 用第一个指令打第一个目标。每个界面和演出都会截图，同时核对游戏状态（等级、道具、Coop、期限、通讯录），并检查日志里有没有报错。画面切换（启动、开始游戏、换场景、进入战斗、战斗结束、潜入和离开潜空间、序章结束回标题、战斗失败）、暂停菜单展开、从菜单进入回看和退回菜单、设置开机、登记界面打开、存档快门、战斗结算和战场上各技能与攻击的特效录成胶片：一张图里 8 到 24 帧，按固定间隔从左到右、从上到下排列。标题立绘另录一张 20 帧的半尺寸脸部特写（间隔 0.1 秒），用来看呼吸、摆头、头发和眨眼。队伍卡片的攻击、受击和胜利表情各录一张只拍卡片那一条的胶片。结果写到 `game/E2E/<时间>/`：报告是 `report.md`，旁边是截图、`build.log` 和 `player.log`。全部检查通过时退出码为 0。

运行期间会弹出一个 1600×900 的窗口，不要碰键盘鼠标。编辑器按 `ProjectVersion.txt` 的版本在 Unity Hub 的安装目录里找，找不到时用 `UNITY=/path/to/Unity game/Tools/e2e.sh` 指定。也可以在编辑器菜单 **System Prompt → 构建端到端测试版** 只做构建。驱动代码只编进编辑器和带 `SP_E2E` 定义的测试版，正式构建里没有。

界面固定按 1920×1080 布局，窗口比例不同时加黑边。斜切面板、网点、爆炸框等用 Painter2D 在代码里画（`UI/Elements/Shape.cs`），USS 负责尺寸、位置、文字和各种 `is-*` 状态。界面配色和字体沿用 PV 的设计，见 [pv/README.md](../pv/README.md)。

画面切换参照 P 系列，在 `UI/Elements/Transitions.cs`。所有转场用同一套做法：要离开的画面先截下来，用滤镜打碎（色差、整行横向撕裂、像素块、缩放模糊、显像管关机）；盖住时是墨色底上一张生成的背景图，加扫描线和红青色差的大字；揭开时盖板带着发光的边退开。现实里用 P5 的斜切，进出潜空间是潜入数据海、浮出终端，战斗是碎玻璃，输了是信号中断，章节结束像关掉显像管，开机和回到标题都从雪花屏里解码出来：

- 启动：雪花屏盖着标题，雪花底下隐约是电路板，电流一圈圈往外扩；随后按随机方块一块块解码出标题，方块边缘亮绿。
- 标题和剧情之间、读档、战斗结束：一列斜切色块从左扫过，扫过时旧画面褪色、色差分开、整行横向撕裂；盖住后是斜着滑过的电路板，底下还有一层更细、更慢的电路板；光点沿着走线跑，一圈圈电流从中心往外扩，点亮经过的走线，数据小方块往上飘；右下是加载条、一行终端日志和放大的 NOW LOADING。
- 剧情换场景：同样的斜切，中间停下显示地点卡；地点卡下面开一扇窗，目的地的背景从马赛克和雪花里解码清楚。
- 进入战斗：探索画面被吸进爆炸框（缩放模糊、色差、变蓝），爆炸框炸开后，碎玻璃不停地迎面飞过，速度线从中心射出，光带横扫过去，ENCOUNTER 色差抖动着砸下来，再沿对角线裂成两半退出。
- 进入潜空间：剧情画面变蓝、碎成像素块一块块熄灭，露出一段沿数据海的井往下坠的视频：聊天气泡、数据面板和气泡迎面冲过去，代码流沿井壁盘旋，光环一圈圈掠过，井底一点冷白光；上面再叠速度线和往上飞的数据块；DIVE 砸下来，下面是 LATENT SPACE // CONNECTING、区域名和往下跳的深度计。潜空间场景在这段时间里搭好，没搭完时井一直往下坠、停在 DIVE 上。最后接着往下坠出井底：文字散开，井加速冲过去，从中心打开一个边缘柔和发光的圆环，露出 3D 场景，镜头同时从主角头顶高处转着降到身后，中间没有闪白和硬切。
- 离开潜空间：3D 画面褪成绿色荧光、从下往上抹掉，露出按列往下落的终端日志：每列速度不同，列头亮、拖尾渐暗（像在往上浮），SURFACE 和回升的深度计，再被一道绿线从上往下扫掉。
- 战斗失败：「掉线……」之后画面整片撕裂，红青色差、雪花和故障画面闪烁，打出 SIGNAL LOST，接着像显像管关机一样压成一条亮线、缩成一点，黑屏后从雪花里解码出标题。
- 序章结束回标题、在标题选退出：显像管关机；回标题时同样从雪花里解码。

切换期间不接受输入。开始 0.2 秒后按确定或取消，剩下的部分三倍速播完、中间的停顿取消。一帧卡得再久也只按 0.1 秒推进，不会让动画直接跳到结尾。潜入时潜空间场景在后台搭：先用 `Resources.LoadAsync` 读入场景模型和两个角色，再每帧搭一块（场景模型的每个文件用 `InstantiateAsync` 分几帧复制进来，再分帧整理和合批，然后是海床、区域装饰、灯塔、道具、残骸、机关和两个角色），3D 镜头在揭开前一直关着，所以潜入视频不会停。场景文字用的旧版 `TextMesh` 第一次创建要半秒，开机第一帧之前先建一个。设置里打开「减少闪烁」时不做横向撕裂和抖动，闪光也减弱。快进剧情时换场景不播转场。

滤镜是 `Resources/Shaders/ScreenFx.shader`。Unity 6.0 的 UI Toolkit 没有滤镜，也不能给元素换材质，所以 `UI/Elements/FxSurface.cs` 每帧用 `Graphics.Blit` 把着色器画进一张 RenderTexture，再用一个 Image 元素显示在界面里。截取旧画面用 `ScreenCapture.CaptureScreenshotIntoRenderTexture`：在帧末截下当时的画面，下一帧原样盖在原处，看不出接缝，之后才开始打碎。着色器按 1920×1080 的界面像素计算，窗口多大效果都一样。背景图不是静止的：着色器能让画面沿中心无尽地往里坠（两份画面错开一档放大、交替淡入淡出），或者切成竖列各自往下落；还能在上面加沿亮线跑的光点和往外扩的电流圈、飘动的数据块和放射状速度线，都是程序生成的，循环不会断。潜入的井是一段视频 `Resources/Art/Transitions/dive.mp4`：`Tools/dive_video.py` 在 Blender 里用卡片、代码条、气泡和光环搭一口每 60 个单位重复一次的井，镜头 8 秒落下一个重复段，所以首尾无缝；Eevee 渲出帧后由 ffmpeg 加辉光、编码。`VideoPlayer` 在开机时就解码好、暂停待命，潜入时播放进一张 RenderTexture，再当作 FxSurface 的画面过同一套滤镜（色差、扫描线、暗角、旋转放大和揭开时边缘柔和发光的圆环）。素材在 `Resources/Art/Transitions/`：数据海隧道、电路板、光带、碎玻璃、故障画面和终端日志是图像模型生成的（原图和提示词在 [assets/ui/transitions/](../assets/ui/transitions/README.md)），噪声图（溶解用的分形噪声、雪花用的白噪声）由 `Tools/transition_textures.py` 画出，这个脚本也把原图压到黑底、存成 JPG 放进游戏，并把横向滚动的光带图做成左右能接上。`Editor/UiAssetImporter.cs` 让这些图平铺（电路板镜像平铺），噪声图不压缩。

别处也用这套效果：日期卡的日期和潜空间区域横幅的地名带红青色差（`UI/Elements/Fx.cs` 的 `SplitText`），滑入时拉开、砸下时合拢；陪伴生登记和角色资料打开时，背后的画面色差撕裂一下再平复；觉醒演出的背景沿数据海一直往下坠，带速度线和光带。

弹窗打开时内容从左下斜着甩进来，菜单项逐个滑入；背后是移动的斜条纹和飘动的数据碎片。

暂停菜单参照《P4 Revival》的菜单（`UI/Modals/GameMenu.cs`）：

- 打开菜单：一道白线横切过屏，绿色笔刷从左扫入，右边斜着滑进同伴的大特写（队伍里的同伴，没有就用最近认识的角色），菜单字一个个旋转飞入，停下时每个字都略歪。光标移到哪一项，那一项的字会跳一下。菜单底色不透明，剧情画面不会透出来。
- 进入子页面（存档、读档、手机、设置、回看）：菜单字散开飞走，镜头猛推进特写，子页面在推进途中接管画面。
- 关掉子页面：镜头从特写拉回，菜单字重新落位。

每个子页面有自己的界面和进出场动画，不管从菜单、标题、快捷栏还是快捷键打开都一样（入场和出场用 `Modal.PlayMotion`）：

- 存档 / 读档（`SaveLoadModal.cs`）：相册。左边是选中存档的大照片（场景图贴在歪斜的相纸上，配胶带）和大号日期，右边是存档卡片，选中的卡片变成白色相纸、带页面色的硬阴影、向左抽出。存档是绿色，读档是蓝色。打开时快门叶片合拢再张开，伴随闪光和快门声（存档上下合拢，读档左右合拢）；存档成功时照片再闪一次，盖上 SAVED! 印章。
- 设置（`SettingsModal.cs`）：终端里打开的配置文件 `system_prompt.cfg`。每页是一个文件标签（`audio.cfg`、`text.cfg`……），每行带行号，写成「键 = 值」：滑块是方块条，开关是 `[ ON OFF ]`，选项是 `◀ 值 ▶`，选中行有闪烁光标，说明以 `//` 注释逐字打出，底部是状态栏。打开时像 CRT 开机（一道亮线展开成画面），各行依次打出来；关闭时缩成一条线再消失。
- 回看（`BacklogModal.cs`）：聊天记录。角色台词是左侧带头像的气泡，主角的台词和选择在右侧（绿色），心声是带绿边的白气泡，旁白是居中的说明文字，系统信息是等宽小条。打开时像录像带倒带：记录快速滚落到位，扫描条划过，右上角闪 ◀◀ REWIND；关闭时快进上滑。
- 手机（`UI/Phone/`）保持原来的手机界面。

剧情对话框也换成了 P5 式的歪斜黑框：白描边、说话人颜色的硬阴影，尖角指向正在说话的立绘；名牌是斜贴的白纸条，选项是错位排列的不规则黑框，选中项翻成白底。快捷栏是一排小斜标签。打开菜单或子页面时，对话框、快捷栏和 HUD 一起淡出，确认框这类小弹窗不会。

战斗结算（`UI/Battle/BattleFx.cs` 的 `ResultsFx`）：墨色和绿色斜带横扫过屏，白色笔刷带出巨型 RESULT，DeepSeek 的立绘从右边滑进、压在面板后面；EXP 爆炸框数字跳涨，每个队员的经验条依次填满（头像循环胜利表情），升级时弹出 LEVEL UP! 爆炸框；掉落物卡片翻入，最后闪烁「▶ NEXT」。按确定后面板甩出画面。集成的收尾特写里，「吃饭饭！」是 P5 式对话气泡，叠在 DeepSeek 前面。

背景粒子在 `UI/Elements/ParticleField.cs`，每个场景在 `GameData.Scenes` 里指定一种：校门和天台是樱花，教室和学生会室是光点，自己房间是夜里的微光，潜空间和战斗是气泡加数据碎片。背景图会缓慢漂移和呼吸缩放。设置 → 辅助 →「背景动态」可以关掉粒子和漂移。

## Live2D 立绘

标题、手机资料页和剧情里的立绘都通过 `UI/Portraits/PortraitView.cs` 显示：切表情、说话人高亮和变暗、说话时动嘴。某个角色有 Live2D 模型时用模型，没有就用 `Resources/Art/Portraits/` 里的 PNG，两种可以混用。战斗里的头像和技能特写也直接用 PNG，队伍卡片的表情帧见上文的战斗界面。

**没有模型时的动态立绘。** 现在三个角色都还没有 Cubism 模型（`.moc3` 只能在 Cubism Editor 里做骨骼和变形后导出）。标题和手机资料页先用 `UI/Portraits/RiggedPortrait.cs` 让 PNG 动起来：立绘画成一张 32×48 的网格，每帧按 `GameData` 里角色的 `PortraitRig`（脖子、脸、身体左右边界、肩线、腰线、闭眼贴片位置，单位是 1024×1536 立绘的像素）弯折网格。效果有：

- 呼吸：腰线以上随呼吸抬起，上半身轻微左右晃。
- 头部：绕脖子缓慢摆动，脸在头部轮廓里朝视线方向偏移，看起来像转头；说话时会点头。
- 视线：标题上跟着鼠标，鼠标不动 2.5 秒后自己四处看。
- 头发：身体左右两侧、肩线以下的长发各自随风摆，有惯性，被点到时会甩开再荡回来。
- 眨眼：每 2 到 5.5 秒一次，偶尔连眨两下。闭眼图是 `Resources/Art/Portraits/<角色>_blink.png`，只覆盖双眼一块、边缘羽化，渐显在默认表情上；其他表情的眼睛位置不同，不眨眼。

闭眼贴片的做法：截取默认表情的脸部，用图像编辑生成同一构图的闭眼版，按图像相关性对齐（三张都无需位移），取两图差异最大的两块区域（双眼）做羽化遮罩，再按遮罩边缘的颜色差校正色调后裁出。换了立绘就要按同样步骤重做贴片，并重新量 `PortraitRig` 的坐标。

有了 Live2D 模型之后，放进 `Resources/Live2D/` 就会优先用模型，`RiggedPortrait` 不再参与。剧情里的立绘仍是静态 PNG。

**安装 SDK。** 从 [live2d.com](https://www.live2d.com/en/sdk/download/unity/) 下载 Cubism SDK for Unity 的内置管线（BiRP）版。本工程用内置渲染管线；最新的 R6 只支持 URP，用不了。下载时要同意 Live2D 的两份软件许可，然后在编辑器里用 **Assets → Import Package** 导入，位置是 `Assets/Live2D/`。Cubism Core 不允许再分发，所以 SDK 不进仓库，已写进 `.gitignore`，每台机器各自导入。`Editor/Live2D/Live2DDefine.cs` 会检查 SDK 在不在，自动开关 `SP_LIVE2D` 编译定义：没装 SDK 时工程照常编译，全部用 PNG。

**放模型。** 用 Cubism Editor 导出运行时文件（`.moc3`、`.model3.json`、贴图、`.physics3.json`、`.pose3.json`、`.exp3.json`），放到 `Assets/SystemPrompt/Resources/Live2D/<角色名>/<角色名>.model3.json`。例如 DeepSeek 放在 `Resources/Live2D/DeepSeek/DeepSeek.model3.json`，战斗形态放在 `Resources/Live2D/DeepSeek_battle/DeepSeek_battle.model3.json`。SDK 的导入器会自动生成同名 prefab，游戏运行时加载它。模型需要满足这些约定：

- 表情文件以剧本里的表情名命名：`smile.exp3.json`、`pout.exp3.json` 等，`neutral` 可以不做。没有对应文件的表情显示模型的默认样子。
- 眨眼用 model3.json 里的 `EyeBlink` 参数组。
- 口型用 `LipSync` 参数组，没有就用 `ParamMouthOpenY`。说话时按台词长度开合；没有配音，不做真正的口型同步。
- 呼吸用 `ParamBreath`，轻微摆动用 `ParamAngleX/Y/Z` 和 `ParamBodyAngleX`。参数缺了就跳过对应效果。

每个 Live2D 立绘有自己的相机，把模型渲染到一张 1024×1536 的贴图上，和 PNG 立绘一样大，界面布局不用改。Cubism 按预乘透明输出，UI Toolkit 按普通透明混合，所以相机输出先经 `Resources/Live2D/Unpremultiply.shader` 换算，否则模型轮廓会发黑。取景按 Cubism Editor 里的画布：整张画布缩放进贴图，所以画布最好也做成 2:3，人物在画布里的位置和 PNG 立绘一致。立绘不在屏幕上时，相机和模型都会停下来。

目前还没有做：模型的动作文件（`.motion3.json`）不会播放；点头和点身体仍然用界面上的头部和身体区域判定，没有用模型的 HitArea。

## 剧本

剧本只在仓库根目录的 `story/` 维护。Unity 只能导入 `Assets/` 下的文件，所以 `Editor/YarnStorySync.cs` 在打开编辑器、每次进入 Play 前和构建测试版前，把 `story/*.yarn` 复制到 `Resources/Story/Synced/`（已加入 `.gitignore`），`Prologue.yarnproject` 编译这个文件夹。也可以手动点菜单 **System Prompt → 同步剧本**。不要直接改 `Synced/` 里的副本。

剧本里的命令（`<<calendar>>`、`<<scene>>`、`<<battle>>` 等）在 `Scripts/Story/StoryCommands.cs` 注册，新增命令也加在这里。说话人决定台词的呈现方式：`旁白` 是旁白框，`系统` 是左侧弹出的系统提示，`屏幕` 显示在手机画面上，`文件` 是终端投影，主角的台词加 `#inner` 是内心独白，DeepSeek 的台词加 `#thinking` 显示在思考框里。立绘表情用行标签 `#face:表情`，可选表情写在 `story/00-prologue.yarn` 开头的注释里。角色第一次说话时自动登场，换场景时清场。

战斗中的提示和台词放在 `Prologue_Battle_*` 节点，由战斗系统在对应时机调用。`<<dungeon 区域ID>>` 进入潜空间探索，探索中的教学、区域、碎片和事件放在 `Prologue_Sea_*`、`Prologue_Deep_*` 节点，节点名、地图、分区和宝箱写在 `Scripts/Dungeon/DungeonData.cs`；这些节点在探索画面的对话框里播放，不能放选项；门打开（`Prologue_Sea_Gate`）、出口出现（`Prologue_Deep_Light`）、维护进度 80%（`Prologue_Deep_Warning`）和第一次被偷袭（`*_Ambushed`）的节点改由 DeepSeek 在右上角播报，只放她的台词。它们只能用探索专用的命令（`StoryCommands.RegisterHints`），目前是 `<<mirror on|off>>`：让出口旁的白门变成镜子、再变回来。

## 存档

存档、设置和已读记录放在 `Application.persistentDataPath`：

| 文件 | 内容 |
| --- | --- |
| `saves/slot_00.json` | 快速存档（F5） |
| `saves/slot_01.json` – `slot_12.json` | 普通存档位 |
| `settings.json` | 设置 |
| `system.json` | 已读台词，用于「跳过未读文字」 |

存档是检查点：每进入一个 Yarn 节点，就记录一次节点名、游戏状态和 Yarn 变量，存档写入的是最近一次检查点，读档时从那个节点的开头重新播放。所以存档界面会提示「从本节开头继续」。战斗和潜空间探索中不能存档。

## 还没做的

3D 校园、序章以外的潜空间区域、日程推进、Coop 剧情、礼物和装备界面都还没开始；目前只能玩序章。潜空间里的噪声体还是几何体拼的，信标还不能存档。Tripo 绑的骨骼没有尾巴骨，绑骨时把鲸尾、垂到背后的长发和挎包分给了最近的手脚，一动就被扯开；导入时把离整条腿或手臂太远的顶点改绑到腰（Hips）或胸口（Spine2），所以便服 DeepSeek 的鲸尾跟着腰整体移动，不会自己摆。战斗服的尾巴有骨骼，只是贴着地拖，还不会自己甩。主角在序章里还不能觉醒，战斗服只在镜子里出现。战斗系统只实现了教学战斗用到的部分（普通攻击、技能、深度思考、防御、道具、One More、集成），数值按 [design/stats.md](../design/stats.md) 计算。
