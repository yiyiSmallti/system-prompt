# System Prompt Unity 工程

这里是游戏本体。3D 校园还在制作，目前做好了：标题画面、陪伴生登记、序章剧情播放（立绘、表情、点击反应、回看）、手机（日程、通讯录、Coop、持有物）、存读档、设置、序章的教学战斗（3D 战场），以及序章里的两段潜空间 3D 探索（缓存海·浅层和深层）。界面全部用 UI Toolkit 在代码里搭，样式在一份 USS 里；潜空间的场景和噪声体由代码用几何体拼出，主角和 DeepSeek 是用 Tripo 生成的人形模型，都配三渲二着色器。没有场景和 Prefab 需要配置。

工程在 Unity 6000.0.85f1（macOS，Apple Silicon）上编译通过，并用[端到端验证](#端到端验证)从标题一路玩到序章结束。

## 打开与运行

1. 用 Unity Hub 打开 `game/` 文件夹，编辑器版本用 `ProjectSettings/ProjectVersion.txt` 里的 6000.0.85f1（Unity 6.0 LTS）。要构建 macOS 播放器还需要装 Mac Build Support 模块，构建 Windows 正式版要装 Windows Build Support (Mono)。
2. 依赖写在 `Packages/manifest.json`：Input System 1.20.0、uGUI 2.0.0（提供 TextMeshPro，Yarn Spinner 需要）、Yarn Spinner for Unity 3.2.8。Yarn Spinner 从 [OpenUPM](https://openupm.com) 的 scoped registry 下载，打开工程的机器需要能访问 `package.openupm.com`。没有改用 GitHub 的 git 依赖：在 macOS 27 上，Unity 包管理进程调用系统 git 会因 Command Line Tools 只有 arm64 而失败。
3. Player Settings 里 Active Input Handling 已经设为 Input System。代码同时支持新旧两套输入，改成 Both 也可以。
4. 打开 `Assets/SystemPrompt/Scenes/Boot.unity`（一个空场景），直接进入 Play。`GameBootstrap` 会在场景加载后自动创建相机、`GameRoot`、UI 和音频，场景里不需要放任何东西。

第一次导入时字体和立绘较大（三套 Noto Sans SC 各 10 MB），会等一会儿。`Editor/UiAssetImporter.cs` 会给 `Resources/Art` 下的图片关闭 Mipmap、改用高质量压缩，把 BGM 压成 Vorbis。`Editor/ModelAssetImporter.cs` 把 `Resources/Models` 下的 FBX 导入成人形骨骼、动作循环，不导入材质（战斗动作按表只留出手的那一段，原地播放——Tripo 的骨骼把整段位移放在胯骨上、根节点不动，所以按重心取出位移再丢掉，否则动作会带着整段位移往前冲（拍照那条冲出四米）；`Props/` 下的道具导入成不带骨骼和动作的普通网格），并把挂错在四肢上的顶点改绑到躯干（见[还没做的](#还没做的)）。Tripo 给便服 DeepSeek 生成了两条鲸尾，一条从卫衣下垂到脚踝，另一块大尾鳍单独立在脚后、不连身体，侧面看像断成两截；导入时只保留连在身上的部分。Tripo 把每个人的下巴都削得很尖：导入时沿头部中线往下找到下巴（脸的正面一步退回脖子的地方），把嘴以下的脸往上收、下颌稍微放宽，下巴短一点、圆一点。它也校正基础色贴图：Tripo 把亮部压暗，白色、灰色和皮肤提亮回去，有颜色的部分不提亮（否则 DeepSeek 的藏青头发会变成发白的浅蓝）；蓝色整体偏青约 12°，转回设定图的靛蓝，发梢补回饱和度。DeepSeek 战斗服生成时把阴影烘进了皮肤：袜口和裙子之间的大腿、脸侧和脖子成了一块块平涂的棕色（约 `#8A6F68`，占皮肤像素的一半），放到人物上是脸颊一道晒痕、腿比脸黑。皮肤的明暗由着色器来画，所以校色之前先把这些像素提回没被阴影盖住的肤色（`Unshade`，只对 `BakedShade` 里点名的模型做：换个模型，同样的棕色可能是皮革）。只按颜色挑会连金色扣件的暗面一起提浅（束腰的扣子、缝线、靴扣成了花斑），所以只动连成片的棕色：贴图里超过万分之 2.4 的连通块才算（一共十块，占这种棕色的四分之三，是大腿和脸侧；金色都是几百像素以内的碎片），每块往外三个像素以内仍是肤色的边缘一起提，免得留一圈棕边。

潜空间里的人物有表情：会眨眼，说话时嘴巴开合；剧本的 `#face:` 标签（smile、pout、scared、sleepy、concerned）换成对应的眼睛、嘴和脸红；战斗里挨打时皱眉，倒下时闭眼，赢了会笑。Tripo 的模型没有表情骨骼和形变，表情是画上去的。编辑器菜单 **System Prompt → 采集角色正脸**（`Editor/FaceCapture.cs`）从正面拍下每个模型待机第一帧的脸，包括颜色和深度。`Tools/face_expressions.py` 在照片上画出 3×3 的表情图集（闭眼、笑眼、半闭眼、小瞳孔，笑、张嘴、撅嘴、o 形嘴，脸红），存成 `Resources/Models/Characters/<模型>_Faces.png`，眼睛和嘴的位置记在 `Tools/FaceArt/landmarks.json`。三渲二着色器把图集从正面投回脸上，跟着头部骨骼走，只画在和拍摄时一样深的脸面上，所以挡在眼前的刘海照样挡着。换了模型要重新采集、重跑脚本（需要 Pillow 和 numpy）。

主角四套模型的眼睛是重画的。Tripo 依据的设定图里脸只有约 60 像素宽、刘海压到眼睛上沿，生成的眼睛发灰发虚、画着发丝，女主角家居服有一只没有瞳孔，战斗服眼皮上一片白斑。`Tools/face_eyes.py` 在正脸照片上按 `landmarks.json` 的位置重画眼睛（虹膜按设定用深灰，战斗服用青绿）和周围的皮肤，再经采集时一并写出的三角形（`Tools/FaceArt/<模型>_mesh.bin`）贴回基础色，只画在脸自己的表面上，挡在眼前的发丝保持原样；结果存成和基础色一样大、只在重画处不透明的 `<模型>_Eyes.png`，导入时 `ModelAssetImporter` 把它叠在校色后的基础色上，原贴图不改。改眼睛的顺序：跑 `face_eyes.py`，重新采集（贴图会自动重新导入），再跑 `face_expressions.py`。贴图上一只眼睛只有 30 到 50 个纹素宽，再细的笔画会糊掉。

DeepSeek 的战斗服不是 Tripo 绑的骨：模型在 Blender 里绑了 Mixamo 骨骼，加 6 节尾骨，权重按部位修过，所以 `ModelAssetImporter` 不给它改绑，也不修下巴。它的文件里没有待机动作：探索时站着用 `Motions/IdleDeepSeek.anim`（动作库的站姿，见下文「走、跑、冲刺和站着」）。她脸上的手绘表情是按原来 Tripo 版待机第一帧的头部姿势对位的，那段待机留作 `Motions/FaceDeepSeek.anim`：`SeaFigure` 建人物时先摆成它量好脸框，再换成现在的站姿（直接在新站姿上量，脸框会歪在头上，眨眼、挨打和倒下的表情全都贴不到脸上）。手绘表情盖住的地方按皮肤着色（`Toon.shader` 的 `Expression` 连同覆盖率一起返回）：闭上的眼睛是画在眼珠上的一块皮肤，原来跟着底下的眼珠算成「不是皮肤」，会染上皮肤不染的区域色调和布料的暗面，闭眼就成了脸上两块灰紫色的补丁，远看像睁着眼。它的头骨在脖子顶端，比 Tripo 的低，所以 `SeaFigure.DeepSeek` 把脸框多往上抬一些。所有动作都是给没有尾巴的骨架做的，会让尾巴跟着胯部整条抬起来：跑步时本该贴地的部分离地最多 24 cm。`SeaFigure` 在每帧摆好姿势之后把尾巴重新摆一遍（`LayTail`）：前两节跟着胯部，后面每节放在各自的高度上（`TailLaid`，是尾根当前高度的几分之几，所以下蹲时整条曲线跟着沉、躺下时整条贴地、跃起时跟着升，最低不低于身高的 3%）。模型文件里这条尾巴从髋部笔直垂到地面、拐个直角平铺在地上，像腿后面立着一根柱子、脚边铺着一块垫子；设定图（`assets/characters/deepseek-outfits.jpg`）里它是一道大钩子：从身后垂到脚踝，绕到她左侧，再向上立起来，尾鳍举到手边。所以尾根向后倾 16°（`TailTilt`）、向她左侧倾 14°（`TailOut`，原来从镜头看正好竖在两腿之间），第四个关节降到小腿的高度，之后重新升起，最后两节（尾鳍）立起来，末端在膝盖以上；它的长度不够既垂到脚踝又举到手边。从上往下看，它下降时往身后走，然后绕到她左侧、上升时又往前折回来（`TailCurl`，各节的走向从正后方依次转 50°、90°、133°、167°、177°），尾鳍立在左腿旁边、横对着她，从前后看都是正面；一路朝同一个方向走的话，这么深的钩子要伸出去半米。尾鳍发亮的背面朝着她身后，游戏的镜头都在那一侧。尾鳍在模型里宽 73 厘米，是她肩宽的两倍：从开始变宽的第五节骨头起缩到 0.72（`TailFlukeSize`），大约五十厘米出头。PV 的星光鲸尾里尾鳍立在她身侧、举到膝盖上下，所以最后三个点的高度从尾根的 0.26、0.36、0.48 抬到 0.28、0.42、0.6，尾鳍原来斜躺在脚踝边，现在从身后看是一道 S 形，尾鳍竖着立在左腿旁。设定图里的尾巴比模型的 1.1 米长一半、比大腿还粗，中间有一版照着把整条尾巴放大到 1.2 倍，连尾鳍一起大得喧宾夺主，现在整条用模型原来的尺寸。尾巴的腹面在贴图上只有背面三分之一的亮度（生成模型用的几张图都没画到这一面），钩起来以后朝着她正面的恰好是腹面，从前面看是一片发黑的东西。`ModelAssetImporter.MarkUnderside` 在导入时把尾巴腹面的顶点记在网格的顶点色里（红色通道为 0；是不是尾巴看骨头的名字，是不是腹面看法线和这一节尾骨「背」的方向相比朝哪边），`Toon.shader` 的 `_Lift` 把这些地方的贴图颜色提亮（`SeaFigure.UndersideLift`，1.6）。没有顶点色的网格读出来是白色，不受影响。尾巴的材质照 PV 的星光鲸尾画（`Toon.shader` 的 `_Starlit`，只给战斗服 DeepSeek 开）：导入时 `MarkUnderside` 还把每个顶点属于尾巴的份额记在顶点色的绿色通道（255 × (1 − 份额)），把它在尾巴上的位置记在 uv3（x 从尾根 0 到尾鳍 1，y 是绕主尾骨一圈的角度 0 到 1，`GetVersion` 升到 16 强制重新导入）。着色器按这两个量把尾巴从深藏青渐变到尾鳍的亮蓝（亮度不变，只换颜色），在 (x × 46, y × 12) 的格子里撒按哈希闪烁的星点（离得远时按 `fwidth` 淡掉，免得变成一片噪点），一道光从尾根往尾鳍慢慢流过去，越往尾鳍边缘光越强，都加在自发光上（`_StarColor`）。（这一轮先试过把它在地上盘成一道弧、尾鳍平铺：从侧面看像一块斜靠在胯上的板，战斗镜头里大半条尾巴在画面外。）钩子只在站着的时候有：一动起来（0.3 米/秒起，1.4 米/秒也就是慢走时全开，`TailStreamFrom`、`TailStreamFull`）各节的高度就从 `TailLaid` 过渡到 `TailStreamed`、钩子展开，尾巴在膝盖的高度平着飘在身后，发亮的背面朝上对着跟随镜头；原来走路时还带着钩子，尾鳍被拖到身后转了半圈，镜头看到的是它发暗的腹面。这个过渡按时间缓动（0.35 秒，`TailStreamTime`）：直接跟着速度算的话，急停或一次出手收势的那一帧速度掉到零，尾巴一帧之内从平飘跳成钩子。胯部降下来时钩子的盘绕也松开（胯高从身高的 0.38 降到 0.22、也就是跪下时松完）：回旋扫收势单膝跪地，钩子会堆在小腿边。战斗里钩子绕向没有队友的一侧（`SeaFigure.TailTo`，`BattleStage` 按站位给：队伍最右边的人绕向右侧）：绕在左边时它正好立在主角脚前，从队伍身后的每个镜头看都挡着主角的小腿，指令镜头里还压在按键提示上；尾根往哪边倾也跟着换。摇尾巴时左右摆 60°，尾鳍跟着抬起来。朝向只跟着胯部左右转，不跟着前倾；胯部朝上或朝下（躺着）时不跟：那时胯部「正前方」在地面上的分量只剩一点零头、指向哪里都有可能，尾巴会在她躺着的时候绕着她慢慢爬。各节再从上一帧的位置慢慢回正，所以跑动和转身时尾巴拖在身后。躺在地上时（`SeaFigure.Lying`）钩子摊平了是一个圈，从身下绕到头边，她正好躺在自己的尾巴上；所以躺下时各节一律朝身体一侧伸出去（`TailLain`，和钩子同一侧）。每节绕自身滚到「横向水平」；这个横向取的是文件里的原始姿势（尾巴在她的正中面里，横向就是她自己的左侧），在尾根倾斜之前就记下，原来是倾斜之后取的，垂着的几节会偏 30° 左右。在潜空间探索里尾巴还会自己动：战斗服的尾巴在上面那个朝向上再叠一个越往尾尖越大的左右偏转（站着时以 0.35 Hz 慢慢摆，跑起来摆幅缩小；高兴时摇一下，约 1.6 秒，频率 1.8 Hz），偏转只在地面方向上，所以始终贴着地；校服的尾巴是另一种做法，见下。校服尾巴的形状按设定图（`assets/characters/deepseek-outfits.jpg`）重摆：VRM 里它的静止姿势是向后平伸的弧线，弹簧的重力又让 16 节一节节往下坠，在游戏里成了一根 45° 斜插到地面的细直棍。`SeaFigure.HookTail` 在弹簧记下静止姿势之前把每一节转到钩子的角度（`TailHooks`，站着和全速跑各一组，按速度在两组之间过渡）：先贴着大腿后面垂到膝盖，再向外向上钩起，尾鳍竖直立到裙摆的高度、两片尾叶朝上；跑起来茎部往后拖、尾鳍照样立着（整条钩子一起后仰的话，尾鳍会向前栽到大腿上）。钩子所在的竖直面从正后方向她左侧转 55°（`TailAside`），立在左腿边；摆在正后方时，从游戏的镜头看尾鳍和它下面的弯钩叠成一团，跑起来两条腿轮流踢到它。尾鳍的横向始终对着她的左右，所以从前后看都是正面，和设定图一样。尾根往裙子里收 3.5 厘米、再往下移 9 厘米（`TailIn`、`TailDown`）：文件里它长在后腰上、卫衣下摆的外面，像一截贴在衣服上的圆桩；下移之后从裙子底下出来，钩底跟着降到小腿、尾鳍在裙摆以下，和设定图的位置一致。尾巴的材质在深度上往后退 2.5 厘米（`SeaFigure.Under`，和里层衣服同一个办法）：跑起来尾柄要从裙子后片穿出去，按原位置画的话它从根部起一路压在百褶裙外面，退后之后贴着裙子的那一段被裙摆盖住，尾巴从裙摆底下出来。尾鳍是一块平板，从茎开始变宽的地方算起占最后 6 节（`TailFlukeLinks`，比两片尾叶自己的骨头早两节），这 6 节摆成一条直线，板才是平的。粗细和大小用尾骨自己的缩放来调（`TailSizes`，每处等比缩放，后面的骨头跟着）：尾根 1.35 倍，往后分三步收到尾鳍前的 0.88 倍，尾鳍 0.66 倍。模型的茎根部宽 9 厘米、尾鳍前只有 5 厘米，设定图里比小腿还粗、往尾鳍收细；尾鳍原来宽 40 厘米，比设定图大了近一倍。变粗的几节也按同样的比例变长。（试过在着色器里沿法线把茎吹粗、只在离尾根一定距离以内生效：钩子把尾鳍带回了这个距离里，尾鳍被吹成一团；也试过只缩两片尾叶各自的骨头，尾鳍在它们交界处被捏出褶子。这两种做法都撤掉了，`Toon.shader` 不再有加粗的参数。）摆钩子时每一节要绕自己的轴滚到位，让模型里横在尾巴上的那个方向（文件里尾巴在她的正中面里往后伸，所以就是她自己的左侧）仍然横在她身上；这个方向在转动任何一节之前先全部记下。原来是边转边取，把「这一节现在指向的水平横向」当成它的横向，上一节只要滚离了水平就是错的，而钩面转到左侧之后每一节都不水平：每节比上一节多滚约 20°，茎被拧了一圈，尾鳍那 6 节拧成螺旋桨，从后面看就是一团皱起来的东西、中间一道黑色的折缝。这条尾巴原来当弹簧挂在髋骨下面、每节跟着上一节甩，守不住形状：每节只有 5 厘米长，而髋部每跑一步要上下起伏 14 厘米，一帧就是 2 厘米多；各节的位置是相对人物记的，每一节被甩开一个角度，下一节再叠一个，到尾端整条对折，在两腿之间乱甩，尾鳍跟着皱。现在由 `SeaSprings.Hold` 把整条链「按住」：每一节各自有一个相对人物朝向的目标方向（`SeaSprings.Aim`，`SeaFigure.Sway` 每帧给），不再从上一节传下来，一节偏了不会带偏下一节；髋骨相对站姿转了多少，目标只跟四分之一；每节最多偏离目标 14°，尾鳍那 6 节 3°；各节的位置跟着髋骨的位置走，髋部的起伏把整条尾巴原样带着，只有 0.2 份水流的推力让它在转身和起跑时慢半拍、往后飘一点；刚度不变、重力清零、阻力 0.6。每节的滚转也直接按「横向对着人物的左右」来定，不再沿链传递。尾巴自己的动作加在目标方向上，越往尾端越大：站着时整条尾巴从尾根像钟摆一样左右慢慢摆（从背后看是横着摆，尾端 ±14°，`TailSway`），钩子同时一张一合（±4°，`TailBreath`）；摇尾巴时同样的摆法摆 ±30°（`TailWag`），钩底左右各甩出去十几厘米。（先试过让钩面绕竖直轴转：茎是垂着的，绕竖直轴几乎不动，只有钩子伸出去的那一小段在转，摇起来只挪几厘米，复查的人说尾巴像冻住了。）跑起来钩子像鲸尾那样上下拍（±11°，`TailBeat`，1.4 Hz），再叠一个差四分之一拍的小幅转动（±4°，`TailSwim`），尾端走的是一个圈而不是来回一条线。站姿和跑姿之间的过渡走一根会过冲的弹簧（`TailEase`，约 1.1 Hz、过冲两成）：起跑时尾巴往后甩过头再回来，急停时往前荡过静止位置再落定；冲刺时比跑步再往后拖一半（`TailSprint`）。尾鳍那 6 节用同一个摆角，整块一起动。贴图 `WhaleTail.png` 的白色腹面改成比背面稍浅的藏青（设定图里日常的尾巴是一色的），原来从正面看是两腿之间垂着一片白。跑起来（1.5 米/秒起，4.5 米/秒全开）尾巴改成游动：一道 1.4 Hz 的波从尾根传到尾尖。战斗服的尾巴跑动时被拖成一条直线，朝向怎么摆都看不出来，所以这道波叠在拖出来的位置上（越往尾尖越大，最多 24°）；校服的是上面说的上下拍。摇尾巴的时机是捡到数据珍珠、门打开、找到光和 DeepSeek 露出笑脸。这些只对探索里的两个人物开（`SeaFigure.Explorer`，`SeaAvatar` 和 `SeaCompanion` 设它），战斗里的人物不开：战斗的动作和镜头是按原样调的。战斗里的尾巴另有一种摆法：被胯部带着走的前两节（`Tail1`、`Tail2`）绕胯部正前方的轴左右摆，站着时幅度 5°、频率 0.4 Hz，再叠一个阻尼弹簧（约 1.2 Hz，半秒内平息，总偏转不超过 25°），`SeaFigure.Flick` 往一侧甩一下：挨打时往背离出手的一侧甩 18°，落地 10°，冲出去时往转身的反方向 12°，轮到自己的回合 8°，摆胜利姿势 15°。偏转每帧都从 `Tail1` 静止时的朝向算起，不叠在上一帧的姿势上：没有任何动作写尾骨，叠在上一帧上会一帧帧积起来，把尾巴甩到身体一侧；`Tail2` 自己不转，因为 `LayTail` 随后把它按回地面，转了也白转；后面铺在地上的几节跟着同一个 0.4 Hz 的节拍在地面上左右摆，一节比一节晚，尾鳍处 ±9°（`LaidSway`），原来只有前两节那几度，从侧面看她身后的尾巴像一块搁着不动的板。人躺在地上时摆动在半秒内淡掉（`SeaFigure.Lying`），免得尾巴扫到身上，甩的那一下仍然有，几下就平息。

两张地图都分成几个区域，每个区域的海床颜色、墙和摆设不同，第一次进入时屏幕左侧打出区域名，有的区域 DeepSeek 会说一两句。浅层：气泡礁（起点）、主航道（沉在海底的巨大手机）、表情包珊瑚林、删帖墓地、灯塔背面、机柜峡谷、维护间、灯塔广场；从起点就能看见灯塔和两道防火墙，要绕灯塔一圈到维护终端，再穿过打开的防火墙回来。深层：裂缝、沉没机房，然后西边的回收站（近，有信标）和东边的长上下文回廊（远，有延时补丁）二选一，最后是白门大厅。矮墙挡路但不挡视线，也挡不住光。机柜墙有立柱、顶檐和踢脚，柜里分服务器、硬盘架、配线架、通风格和空挡板，柜顶有转动的风扇；柜门的缝、托盘、把手、通风格和立柱的凹槽按法线打光，有真实的凹凸和高光，主角身上的光会在近处的柜面上照出一圈亮面；海床铺成一米见方的地板，偶尔有透出冷光的通风孔，墙脚一圈接触阴影把墙压在地上，地砖的倒角在主角的光里反光；通道一侧的墙脚散着硬件碎块、发光的数据碎片和从踢脚进出的线缆。走廊里还有 Tripo 生成的残骸（`Dungeon/SeaModels.cs`），按区域挑：死胡同尽头塞着倒下的机柜或线缆盘，拐角立着线缆盘、数据晶簇、电路板珊瑚或旧显示器，墙边躺着倒下的机柜、线缆堆或硬盘堆。残骸挡脚，不挡走廊中线，脚下有一圈区域颜色的光；离道具、机关、噪声体和巡逻点太近的格子不放。

两张地图的布景和战场四周的机柜环是在 Blender 里建模的（[assets/scenes/](../assets/scenes/)，每张图有自己的建模脚本、说明和预览），导进来后由 `Dungeon/SeaScene.cs` 按材质名把模型里的纯色换成游戏的三渲二着色器：风扇绕轴转，漂浮物上下浮动并慢慢自转，其余静态合批。海床、道具、机关和各区域的装饰仍由代码生成，模型里同名的部件在运行时藏起来；碰撞只看地图格子，模型只管画面。浅层的主模型是 587,625 个三角形（预算 600,000），38 个材质，2741 个网格对象、362 份网格数据；外圈的机柜堆（45,226 个三角形）和漂浮碎片（2,916 个）是另外两个文件，不算在里面。建模、校验、导出和重建的命令见[浅层的说明](../assets/scenes/cache_sea_shallows/README.md)。

浅层的布景里有几处是专门做的。气泡礁的聊天气泡是圆润的枕头形（四面都圆、两端微鼓，一套 816 个三角形，矮的 272 个），光在上面不会整片一样亮；每个的正面有三颗「正在输入」的圆点，用礁区薄荷色的发光材质。着色器给枕头一套软的看法（`Toon.shader` 的 `_Wrap` 把明暗交界在曲面上摊宽，`_Inner` 和 `_InnerColor` 让正对眼睛的地方偏亮，`_Sheen` 是海面的光落在上面的一点柔和高光，描边用本色的深色而不是墨色）；白枕头压得最克制：亮面 `#B8C6E0`、暗面 `#7486AE`，边缘光和高光都调低，提亮色任何通道都不超过 0.9，因为近看时它的整个正面会落进高光，顶边从镜头的高度看过去会白成一片，一片白就看不出圆了。海里被丢掉的东西漂在看得见的高度：近水面处的碎屑更大更密（160 片，一个粒子最多占画面高度的 7%，免得抬头看灯塔时从镜头前飘过一片，把灯室盖住）；48 个漂浮摆件（聊天泡、删帖卡片、表情球、像素块）放大后挪到走道上空，离地 10 到 17 米，玻璃和发光的放大 2 到 3 倍，别的 3 到 4 倍（叠加发光的两片重叠时会往白里叠，所以放得小些），并且不放在主航道、广场和灯塔背面，那是从航道和广场看灯塔的视线；八处冒泡口（`DungeonDef.Vents`：礁区的几面墙脚、手机的两侧和广场上）各冒一柱气泡，脚下一团微光；六道从海面落下的光柱，四道在灯塔周围 18 到 30 米外朝海的一侧，两道在起点通往灯塔的路两边、离路 24 米（再近，走在路上、镜头在眼睛高度时会站进光柱里，画面上沿被洗白），各自用 8 到 12 秒缓缓明暗起伏。这一套只在浅层（`DungeonDef.NearSurface`），深层离海面远，碎屑少而小，光柱是九道、离得远。

浅层灯塔的两道光束向下倾 32°（深层的不倾，平着转），每秒转 12°，光落在海床和机柜上，扫过去是一块明亮的光斑：海床上一块浅色的光，机柜上偏亮的蓝，人物身上只有一点（`SeaCommon.cginc` 的 `SeaBeam`，在着色器里算，没有真的灯）。倾下来的光束转得慢，每处每 15 秒被扫过一次，所以从浅层的任何地方都能看到灯一明一灭。这束光只在浅层的迷宫里亮，战斗和深层的 `DungeonWorld.ApplySea` 把 `_SeaBeamColor` 清掉。强度压得克制：海床上的光按「离白色还剩多少」往上叠（`Seabed.shader`，不会烧成白），机柜上只取四分之一、再留一半自己的色相（`Toon.shader`，深色的机柜被照成偏亮的蓝，不是灰），人物更少，不然深色的卫衣会被扫得发白。

表情珊瑚的头长在茎上，土丘上是六个六棱的小锥，表情有六种：笑、眯眼笑、平嘴、哭（带冷白色的泪滴）、捂脸和 XD，每组珊瑚混着用。珊瑚林入口旁的 (8,13) 是一丛单独建的主珊瑚：一颗 0.8 米的大头低低地在前面用手捂着脸，后面高处一颗笑、一颗哭，转 15° 让捂脸的那张脸对着从走道往北过来的方向，手的颜色和头对着来（粉头金手、金头青手、橙头青手、青头金手）；第一次进珊瑚林时 DeepSeek 说「那棵捂脸的，大概是我种的」，说的就是它。珊瑚、海草和机柜顶上垂下的线缆在水里摆，摆动写在顶点着色器里（`Toon.shader` 的 `_SwayAmp`、`_SwayAnchor`、`_SwayLength`，`SeaCommon.cginc` 的 `SeaSway`，按世界坐标算），所以它们仍能和别的东西一起静态合批：珊瑚头在茎上摆 0.12 米，海草从海床往上越往梢越大、摆 0.2 米（叶片两面都画、没有描边），线缆从机柜顶往下垂、摆 0.25 米。海草是四丛扭着的飘带叶，每丛三到五片，高 1.6 到 2.6 米，带 S 形的弯，只占墙脚一米宽的一条。墓地的低墓碑是一对圆拱碑，两面刻着「已删除」，碑底沉进海床 0.15 米，每块按格子的哈希前后倾 4 到 7°、左右转 4 到 7°，一半的格子再转 180°，倾斜了也不悬空；隔一座墓碑，南边的海床上放着一份供品：一张脸朝上的笑脸，周围立着三盏粉红的小灯，像花；地上还有一层贴着小腿高度的红雾（55 团大而软的雾团，每团 20 秒缓缓一进一出，不上升）。机柜峡谷南北向的走廊上，在两边的机柜顶之间拉着线缆（`SeaDecor.Cables`）：按格子的哈希留下约一半，不像梯子的横档那样整齐，最多 12 处；每处一到三根，各垂到自己的深度，最低的一根离地 6.35 到 7.8 米，高过镜头不会撞上，所以默认视角里要从二十多米外才在画面上沿看到，抬头就全看到了；两端有峡谷色的发光插头，两颗数据包（一颗亮珠裹一团柔光）每秒 1.5 米沿中间那根跑，整根线缆像摆锤一样绕两端的连线微微摆（5° 加 1.5°）。这些线缆用 C# 摆而不是着色器，因为着色器的摆动按每格的相位算，会在格子边上把一根四米以上的线缆拧出折角。

主航道里沉着一只巨大的手机。屏幕上是一段聊天：左边白色气泡、右边绿色气泡、一道裂缝和一个红色的未读角标（`SeaArt.PhoneScreen`，512×512，开机时画一次、整个运行期保留），贴在屏幕上方 2 厘米处（模型没有 UV，不能直接贴图，屏幕的位置和朝向是从模型的网格里找出来的）；它跟着灯塔灯的一呼一吸每 4 秒亮一次，像来了一条新消息（透明度 0.6 升到 0.9 用 0.3 秒，再 1.5 秒落回），屏幕光在海床上留一块 19 米宽的浅色光斑。屏幕东边 3.5 米、上方 4.5 米浮着「在吗」的全息气泡（气泡 5.2 米宽，字 1.7 米高，上下浮动 0.15 米），右上角一个未读角标：暗红的实心圆盘，一个深色的「1」。放在这里，是为了让它既出现在从起点看过去的灯塔旁边（塔身的右边、灯室下面），又不压在起点往灯塔去的中轴线上，不叠在防火墙的框或灯塔上；气泡底下垫一层深色的半透明底，字才压得住防火墙的红光和机柜的灯；角标不用亮红，因为亮红会泛光。有人站到它和镜头之间时（主角或 DeepSeek 的头，或一只噪声体，在镜头看过去离它 3.5 米半径的视角以内），它在 0.3 秒内淡到四分之一，人走开再淡回来，免得压在人物身上。

机柜墙脚的杂物（硬件碎块、发光的数据碎片、线缆）在 Blender 场景里同样有，由代码撒在墙脚（`DungeonWorld.Litter`）；浅层再加一种水晶簇：每个朝向空地的墙面有 34% 的机会长一丛，三到五根六棱柱，十五到四十厘米，取所在区域的灯色，侧面大半被海里的光照亮、三分之一发光，尖端更亮，所以每个面自己受光，读得出是切开的石头，不像一张剪纸；水晶只在浅层长（`SeaArt.Scatter` 的 `crystals`，由 `DungeonDef.NearSurface` 打开），深层的墙脚只有前面说的那些杂物。灯塔广场的地面染成海床的蓝（`#9FC4FF`，强度 0.45），不用近乎白的颜色，灯塔的白光才压得住它；三圈脉冲环随灯塔的呼吸（4 秒一次）从里往外扩，每圈隔三分之一个呼吸，最大时半径 10、16、22 米；围着广场的矮墙上隔一格立一盏灯柱，共八根，灯泡 0.35 米，裹着一团 2.6 米的柔光，远远连成一圈；灯塔所在的小岛四周长着放大 2.5 倍的水晶簇，用冷浅蓝，白的会越过镜头的阈值、看不出面。浅层的这些在「减弱闪光」打开时收敛：灯塔光束落在地上的光减半，灯的呼吸只有平时的四分之一（±5%，平时 ±20%），广场的脉冲环不再扩、停在亮度 0.2，手机屏幕稳稳亮着（0.7，不再每 4 秒闪一下），海面光柱的起伏收到 ±5%。

潜空间按 HDR 渲染，探索相机和战场相机各装一个镜头（`Dungeon/SeaLens.cs`，`Resources/Shaders/Bloom.shader`）：超过阈值 1.2 的光逐级缩半再放大，叠回成一圈光晕；画面四周压暗成深蓝；亮部在 0.92 以上渐近白色而不截断；最后加一层固定不变的抖动，免得深蓝的渐变出现色带。只有自发光会越过阈值：`Toon.shader` 把受光的颜色压在白色以内，再加自发光和战斗特效的光，所以机柜的指示灯、灯塔的灯室、复位台的按钮、机关的棱镜和角、深层裂缝里的裂纹会发光，被光照亮的墙和地面不会。信标的灯和数据珍珠自己压在阈值以下，发光靠它们身后的一片光晕：一整颗过阈值的球贴近镜头时会糊成一个没有细节的白盘，珍珠就读不出是珍珠。新做的发光体要让 `_Emission` 的最亮通道超过 1.2 才亮；大块的自发光贴着镜头会把整幅画面泛白，所以白门的白是靠明暗两色做出来的，只加一点蓝色自发光、亮度压在阈值以下，只有门缝发光。两台相机的参数不同，各有原因：战场的光晕宽（最多七级，拐点 0.5，暗角 0.2），收光时每个通道各自收，够亮的光都烧成白热，战斗特效的芯子要的就是这个；迷宫的光晕收得紧（最多四级，拐点 0.2，暗角 0.3），一束光从镜头旁边擦过不会把画面雾住，而迷宫里每个区域的灯有自己的颜色（深层裂缝橙、长上下文回廊的灯带淡紫、峡谷青），各通道各自收会把它们全烧成白、区域的颜色就没了，所以对饱和的光，迷宫按最亮的那个通道收、保住色相；本来就近乎白的光（白门、光束的白芯）仍然烧成白，按最亮通道收会把它们缩成偏蓝。打开「减弱闪光」后光晕强度降到 0.6。

迷宫的布景给镜头和主角让路（`SeaCommon.cginc` 的 `SeaFadeKeep`）：Blender 场景、区域装饰和残骸离镜头 0.9 米内被固定的 4×4 抖动网点逐渐打掉，2.8 米外才完整；镜头和主角胸口之间的一条管子里也同样打掉，所以镜头和主角之间隔着机柜或气泡堆时，它们在主角周围散成网点，不会把人挡住。主角脚踝以下露出来的部分（脚前的一块平台、边沿横过鞋面的台阶）保持完整：在那上面打网点遮不住什么，只会在鞋子周围多出一圈碎点。网点钉在屏幕上、不随时间变，不会闪；用的是丢弃像素，不透明的东西仍然写深度、不进半透明排序。发光的面片、场景文字和光束没法打网点，在同样的距离上改成淡出。人物、道具、珍珠、机关和海床从不消失，战斗里什么都不消（只有迷宫给 `DungeonWorld.ApplySea` 传 `fade`），特效要一直贴到镜头前。

海面透下来的光是一张全场共用的无缝网（`SeaArt.Caustics`，256×256，开机时生成、整个运行期保留）：晶格的边线随海面起伏漂动、抖动，再乘上另一张反方向漂的更大的一层，亮结沿着线游走，整张网不是刚性地平移。它落在海床、布景和机柜的顶面上，仰头时也出现在头顶的海面上（天空那一层更淡，还乘了一层大块的明暗，看着是涌动的海面，不是一块平铺的天花板）；离镜头 1.5 米内不显示、4.5 米外才满，贴近镜头时它只会是几块粗大的涂抹。深层离海面远，只有浅层的 0.45（`DungeonDef.Caustics`）。战场的环形机柜用迷宫的材质，也有这张网。机柜的指示灯会闪（`SeaBlink`）：约四成的灯各按自己的节奏暗下去（0.6 到 3 Hz，最低到 25%），每个面上的每一排灯节奏不同，相邻的柜子不同步；一条灯带始终整条一起明暗，从不切成几段各闪各的，相位沿着灯带走，暗下去或亮起来的那一小截沿着灯带移动；另有一小截更亮的数据包每隔几秒沿灯带跑过，深层裂缝的裂纹则缓慢起伏。战场环形机柜的灯只会轻轻暗一下、不会比平时更亮，也没有数据包（它们本来就压在阈值以下）。「减弱闪光」打开时闪烁慢一半、最低只暗到 60%、数据包变暗，机关缓存块四角的光也不再起伏。

布景越靠近海床越暗（`Toon.shader` 的 `_FootDark`，在 3.5 米高内过渡：机柜 0.6、岩石 0.65、墓碑 0.7、白门大厅 0.8），像接触阴影一路爬到墙上；走到一块硬面前，主角的灯在上面留一块边缘分明的卡通高光（法线接近灯和眼睛的半角方向时才亮，不是柔和的光斑，贴近了才看得到，也不会触发泛光），机柜的金属和手机的玻璃最强，岩石、珊瑚和墓碑只有一点，白门大厅没有，好让白门仍是大厅里最亮的东西。人物按所在区域给阴影染色（只对人物）：海床的光从下方和侧面、海面的蓝从上方，取它们的色相（归一到同样的亮度）染进阴影面，阴影里染得重、受光面只染一点，衣摆和袖口下方再多一点海床的光，皮肤只取一小部分，脸和脖子的颜色不变。人物的光从镜头一侧打来，游戏镜头里他们大多在受光面，所以受光面也要染一点才看得出：灰色卫衣在深层裂缝偏暖红，在长上下文回廊偏紫，在主航道偏蓝。走进另一个区域时用一两秒渐变过去，穿过不属于任何区域的走廊时保持原样，战斗保持开战时所在区域的颜色。人物的边缘光也收窄了：只留轮廓上一圈，越往下越淡，发片的背面没有，卫衣的褶皱和头发里面不挂碎碎的青色光点。Ultra 画质档（独立播放器的默认档）开 4× MSAA；VRoid 模型的头发和衣料这类镂空部件把边缘交给 MSAA 当覆盖率（`Toon.shader` 的 `_AlphaToMask`，覆盖率在 `_Cutoff` 附近收成一个像素宽的斜坡），发梢和布边不再是一格一格的台阶。

水有分区的空气（`Dungeon/SeaAtmos.cs`，各区的数值在 `DungeonData.cs`）：雾的颜色和浓度、贴着海床更浓的低雾、抬头时远处的高东西融进去的水面色、按通道的吸收（红光先没）、灯光比它照亮的东西传得更远，再加镜头的调色（增益、饱和度、暗部的颜色、暗角）。浅层的气泡礁偏青绿，灯塔一带通透，灯塔背面是深蓝，珊瑚林偏紫，墓地是暗红、低雾重、颜色淡，维护间是冷的灰青、几乎没有低雾，峡谷更浓；深层的裂缝偏暖、暗部带红，沉没机房的暗部偏琥珀，长上下文回廊是靛蓝，白门大厅亮蓝，回收站灰而淡。每个区都留着蓝调，没有纯灰的。走过区域的边界时不是切过去，约一秒半渐变过去（传送、读档和潜入是直接到位）；第一次走进白门大厅时先亮一下，再落回大厅自己的亮度（「减弱闪光」打开时只亮一半、更慢）。战斗继承遭遇时所在区域的空气，战场的地面另有自己的一套；潜入结束后的剧情战斗在没有分区的海里打。所有着色器的雾都走 `SeaCommon.cginc` 的 `SeaFog`，这些全局量全为零时和没有分区时算出来的一样，所以标题、镜子的相机和地图之外画的东西不受影响。

人物和噪声体是落在场景里的（`Dungeon/SeaShade.cs`）：相机在画不透明物体之前，先把他们单独画进两张图，一张是从斜上方看下来的深度（1024 见方，探索时围着主角 14 米，战斗时围着战场 20 米），一张是相机自己看过去、只有人物的深度。海床按前一张在他们脚下压暗，影子短、多半就在脚下：深度先模糊成一张遮光图（`ShadeSoft.shader`，每个像素上方有东西挡着就记一笔，离地近的脚和小腿记进窄的一档，高处的躯干、头和被打飞的噪声体记进宽而淡的一档，横竖各模糊一遍），海床只读它一次；原来在海床上逐点比深度，影子的边是一格一格的台阶。原来的圆影在这张图盖得到的地方退成一小片接地的暗。人物的轮廓光按后一张画成贴着身体外沿的一条均匀的亮边（`Toon.shader` 的 `DepthRim`），不在卫衣的褶子、头发和脸上冒青色的碎点。镜子的相机没有这两张图，照旧用原来的轮廓光和圆影。为了让人物在暗蓝的场景里更跳，轮廓光整体乘 `_RimGain`（`SeaFigure.RimGain`，1.8），主角是青色、DeepSeek 偏冷的淡蓝（`PlayerRim`、`DeepSeekRim`）。人物身上还有一道数据扫描光带（`_Scan`，两个人物都开）：每人每 5.5 秒一次（起点按人物位置的哈希错开，两人不同时扫），用前 0.16 拍从脚扫到头顶上方，一条亮线，线下面一截按格子闪的像素点，线上面一层淡淡的光；其余时间不画。战斗服 DeepSeek 的耳鳍和蝴蝶结自己发光（`_Trim`、`_TrimColor`）：导入时 `ModelAssetImporter.Trim` 在头骨权重的顶点里按离头顶的高度、左右偏离和前后位置找出它们（高度按头骨到头顶的距离归一，不受模型尺寸和朝向影响），把份额写进顶点色 B（耳鳍 1、蝴蝶结 0.5）；着色时耳鳍整片泛冷白光、边缘更亮，蝴蝶结只在本来亮的蓝色部分发光，两者随呼吸明暗。

两个人物身上都戴着光做的配饰（`Dungeon/SeaTrinkets.cs`，`SeaFigure` 建人物时一起建，探索和战斗都有）：每只手腕上一圈柔光带（在小臂往手的 86% 处，跟着骨骼转，微微明暗）；腰间一圈慢慢绕身体转的光点，每颗活两三秒、拖一小段光尾，主角是小小的方形像素，DeepSeek 是星光；DeepSeek 头顶还有一个数据光环（PV S11 她变身时那样）：一道细光环，里面一圈刻度反着转，浮在头顶上方、大半跟着头倾斜。它们都用 `Glow` 着色器叠加画，不写深度，所以 `SeaShade` 的影子和深度轮廓光不算它们，集成的墨色画面里也照样亮。手腕光带压在泛光阈值下面：DeepSeek 戴白手套，原来亮一点就泛成一团白球。

人物有一道墨线（`Toon.shader` 的 `_OutlinePx`，`SeaFigure.Line`）：还是反面外扩的壳，但宽度按视线方向的深度换算成画面上固定的 1.25 像素（按 900 高的画面算，在世界里限制在 0.8 到 11 毫米之间，特写时略粗、远处不会把手指吞掉），颜色取这块材质自己的颜色压暗（`_OutlineTint`：炭灰上衣是近黑、蓝头发是藏青，皮肤是暖棕色），镂空的部分线跟着镂空的边走，和本体一样按 MSAA 覆盖率收边。盖在脸上的眼睛、眉毛、睫毛和嘴不描；Tripo 生成的模型皮肤上不描（`_OutlineBare`，壳在顶点上按贴图里的皮肤比例收掉），头发和衣服照描。没有线的时候人物是几块平涂的颜色，手臂和身后的身体分不开。头发另有一圈高光（`_HairGloss`）：法线从朝上转到朝向镜头的那一带，沿发丝方向（贴图的 u）打散成一缕一缕（每条发片大约一缕；条纹比像素还细时按 `fwidth` 抹平，不然高光会随动作闪），只在亮面上有；黑发用灰蓝、DeepSeek 的蓝发用浅蓝（`SeaFigure.HairGlossOf`）。原来头发是一整块纯色，看不出是头发。VRoid 人物的脖子上有下巴投下来的一块影子（`_Chin`，`SeaFigure` 每帧把头骨的位置和朝向传给身体皮肤的材质）：脖子正面从下颌往下到头骨下方 9 厘米，下巴正下方最深、往两侧抬高，边缘是画出来的硬边，只限脖子那一小块（头骨以下、往前 8 厘米、左右 6 厘米以内：这张皮肤也是手的，举到脸前的手不该进影子）；人物身上没有任何灯光投影，少了这一块头像是贴在脖子上的。皮肤的明暗交界处偏暖（交界线正中红通道 +7%、蓝 −7%），是手绘里沿阴影边缘的那道红。

人物按二次元游戏的三渲二画（`Toon.shader`，`SeaFigure.Dress`）：亮面和暗面是两块平涂的颜色，中间一道画出来的硬边，不是渐变。主光跟着镜头走，从镜头右上方打过来（`key`），所以不管人物朝哪边，每个形体都有一侧亮、一侧暗；原来光贴着镜头正上方，整个人几乎全是亮面，暗部颜色又浅（0.78），看起来是一块块平色的 3D 模型。布料的暗部是自身颜色乘一层偏冷的紫（`SeaFigure.Shade`，0.6 / 0.58 / 0.78），再提一点纯度（`_ShadePure` 0.2），皮肤的暗部是偏粉的肤色（`SkinShadeOwn`），眼白在刘海影子里只是灰紫（`EyeShade`）。交界线的宽度是 `_Wrap`（VRoid 布料 0.06）和 `_SkinEdge`（VRoid 皮肤 −0.03 到 0.05），最细不小于一个像素；VRoid 卫衣的袖子上建了褶，硬边沿着褶走成一排折线，当作画出来的衣褶留着。Tripo 生成的战斗服贴图里已经画了明暗、表面又不平，暗部浅一档、边放宽（`ShadeDrawn`、`ClothWrapDrawn` 0.14），皮肤仍然要转过去很多才变暗。

脸不按自己的表面算明暗，按绕着头的一个球算（`_FaceRound`；`SeaFigure.LegsUnder` 每帧把头骨的位置、人物身高、头朝上和朝前的方向传给人物的每个材质，`_HeadAt`）：鼻子、嘴唇、眼窝各有一小块阴影会把脸弄脏，生成的脸法线不平还会碎成斑块。球在上下方向压扁，所以明暗边竖着走，头转离光时从背光那侧的脸颊往里推，和二次元游戏用的脸部阴影图是一个效果；正对镜头时只有那侧脸颊的边缘在暗部。VRoid 的脸和盖在脸上的眼睛、眉毛、睫毛、嘴整个材质都这样算（1），Tripo 的模型只有头附近的皮肤这样算（2）。

人物会把影子投在自己身上（`CastShade`，`_CastOwn`）：刘海投在额头上、下巴投在脖子上、领口和袖口投在里面的衣服上、裙摆和衣摆投在大腿上。潜空间里没有灯也没有阴影贴图，用的是 `SeaShade` 已经为边缘光画好的人物深度图：从表面朝光的方向走 12 步（每步 1.35 厘米，共 16 厘米），哪一步落在比光线更靠近镜头 4 毫米到 14 厘米的东西后面，就在影子里；投影用的光比主光更陡（`overhead`），影子落在投影物的正下方。深度图每个像素只有一个点，每一步在最近的四个像素之间按位置加权，影子的边才不是锯齿；离表面只有一两厘米的东西（短裤的裤脚）在光线后面的那段比一步还短，逐步去试会让影子的远端变成一级一级的台阶，所以光线第一次钻到某个东西下面时，在前后两步之间二分三次找到钻进去的位置，在那里再试一次。脸上只认离脸 8 毫米到 5 厘米的东西、只走七分之一的距离（2.4 厘米）：只留刘海正下方那一道，不让头两侧的每一绺头发都在脸颊上划一道，也不让鲸鱼兜帽的帽檐把整张脸罩进暗部；Tripo 的脸不接受投影（刘海和额头是连在一起的一块，鼻子和不平的表面会在脸颊上投出碎块）。深度图从半精度改成了全精度浮点：半精度在镜头常用的距离上一格是 4 到 8 毫米，和刘海离额头的距离一样粗。镜子里的人物没有这张深度图，不投影。

人物身上的其它处理：穿在里面的衣服画得比实际位置靠后一点（`_Sink`，`SeaFigure.Under`：校服 DeepSeek 的白衬衫后退 1.2 厘米，屏幕位置不变，只改深度；再多就连衬衫底下的肚子都盖到衬衫前面来，3 厘米时腰间露出一条身体贴图的黑边），身体一弯就从鲸鱼卫衣前襟里透出来的白块没有了。男女主角的家居服上衣又长又松、垂过大腿，衣摆的权重只跟着髋，抬腿时一动不动，短裤和裤腿就从衣摆前面穿出来：现在上衣的每个顶点都被挡在两条大腿之外（`_Legs`，`SeaFigure.OverLegs` 按材质给出大腿根和膝盖处的粗细，`LegsUnder` 每帧把两条腿当成两头粗细不同的圆柱传给着色器，落在圆柱里的顶点沿径向推到表面），衣摆搭在抬起的大腿上；圆柱从大腿四分之一处才开始，站着时衣服的形状不变。这件上衣的里侧按外侧一样的亮面画（`_BackLit`）。它的贴图是抹掉兜帽和抽绳后整件填成一种灰，但卫衣原来的深色还剩了几处：兜帽根部在领口两角各一块、两条袖缝各一道线、下摆的罗纹是一排近黑色的锯齿（抬腿时在衣摆边上像短裤穿出来的黑牙）。`ModelAssetImporter` 导入这两张贴图时把明显比主色深的像素都填成主色（`Plain`，`PlainTops`），透明度不动，衣服的轮廓照旧。填平以后按设定图（`assets/characters/protagonist-*-outfits.jpg` 的家居服）重画成针织面料（`Knit`）：颜色从填充用的中灰改成深炭灰 `#3A3B43`，加一层细颗粒和顺着布料往下走的宽褶，下摆、袖口和领口各一圈罗纹（深一档、带竖向细纹，接缝处一道深线；领口那圈按离领口边缘的距离画，30 个像素宽）。女主角的短裤在设定图里裤脚有白色包边，贴图（VRoid 的黑短裤）没有，导入时把裤脚那一带画成白色（`Pipe`，`Piped`）。胸口抽绳孔那个一厘米左右的小凹坑是网格上的，还在。VRoid 模型的头发、裙摆和帽绳是弹簧骨（`Dungeon/SeaSprings.cs`），跟着角色自己的坐标算，匀速跑的时候没有任何东西推它，长发就直直垂成一堵墙；尾巴和髋鳍相反，留在世界坐标里、每帧阻力近一半，跑起来被拉成一根水平的棍子。现在每一节都按它的关节这一帧在水里走过的路往回推一份（头发 0.16，裙摆、衣摆和帽绳 0.04，胸部不推；髋鳍只按 0.2 拖在后面，同时每走一米往下沉 0.14 米）：跑起来长发往后飘、停下来落回去，髋鳍拖成一道下垂的弧。校服的尾巴后来不再这样拖着，改成按住钩形（`SeaSprings.Hold`，见上文 DeepSeek 一段）。

海床是湿的（`Seabed.shader`）：墙脚的灯光往地上溢出半米到一米多，远处贴着视线的地面泛水面的颜色，十四米外的网格线淡到六成，泥沙有大片的深浅；战场的地面上，特效的光和灯有清楚的倒影。深层裂缝区的裂纹直接画在海床上：约 1.8 米一格的网，被扯开成走向和分叉，红橙的芯、暗的边，慢慢地明暗（「减弱闪光」时减半）。水里有浮游的光点顺着水流漂，近处有几颗大而虚的从镜头前掠过，深层有气泡从海床升起（`Dungeon/SeaFloaters.cs`；「背景动态」关掉时没有近处的光点和气泡，数量减到四成、不摇）；深层的水面光柱只画镜头前方最近的十根，战场上噪声体身后有三根。信标、终端、出口、珍珠、防火墙和裂缝的光会照到附近的墙和人身上（`Dungeon/SeaLights.cs`，每帧取最近的四盏，进出时渐变，所以不会跳）。长上下文回廊里的聊天记录越旧越淡，最后一条是「…（已截断）」；沉没机房的行号牌是深色底板上的琥珀色字。

噪声体在地图上巡逻，碰上就进入回合制战斗：走近按 Enter 攻击，没被发现时是先制攻击，背对着被追上的噪声体撞上是被偷袭。打倒的噪声体从地图上消失，信标回满 HP 和 SP，战斗失败回到标题。信标是一座小灯塔：八角塔身绕着几道光带，玻璃灯室里一盏灯，两道光从灯里扫着转，屋顶上立起一根光柱，地上一圈圈光往外扩；休息的那一下灯转成绿白色、之后一直是绿的，海床上荡开一圈光环、溅起光点，「HP 和 SP 已回满」的提示等区域名的横幅收掉再出，两样不叠在一起。标题党型是一扇长了脸的弹窗：红黄闪烁的像素方块排成宽扁的窗口，顶上一条红色标题栏、右端一个白色关闭钮，标题栏下面是眼睛，再往下横着一张黑洞洞的嘴、两头各一颗白牙（标题栏、关闭钮、牙和嘴里的颜色固定不闪，由体素的顶点色指定），不时有方块跳出来，底下往下掉像素，身边接连弹出「震惊！」「点击领取」之类的广告窗；转发型是一只箭头刺猬：身子是 Blender 里做的圆滚滚的刺猬（尖鼻子、小圆耳朵、四只短脚，`assets/characters/noise/repost_body.py` 生成，FBX 在 `Resources/Models/Noise/`），背上和两侧插满往上往后长的分叉箭头当刺，箭头轮流往外一顶，不断复制出往两边飘散的残影。每只噪声体有自己的时钟和种子（`NoiseLook`，着色器的 `_Clock`、`_Seed`），所以两只同类不会按同一个节拍闪烁；标题党型窗框上被啃掉的边角和背上凸出的方块也各不相同（五种轮廓），大小在 0.94 到 1.06 倍之间，朝向偏几度。噪声体的眼睛表明状态（`NoiseMood`）：打盹时眯成一条暗蓝灰的缝、身子微微歪着、头上冒 Z，平时偶尔眨一下，起疑时睁大成琥珀色，追赶时斜成怒眼、微微发抖。追赶的眼睛画成白热的发光色，嵌在一圈加宽的深色眼眶里，红色只留给它四周的光晕：追赶时噪声体整个皮肤都是红的，纯红的眼睛落在红格子上就看不见了，所以眼睛靠比格子亮、再被深眼眶衬出来才读得出。被打中时眼睛眯成一条线，倒地时半闭着打转。人物和噪声体脚下都有一团接地阴影。觉醒前主角一个人用截图战斗，DeepSeek 在灯塔入队后两人一起打。DeepSeek 觉醒前穿周末便服（卫衣裙），在灯塔觉醒后换成战斗服。

碰上噪声体到战斗转场之间有 0.75 秒的地图演出（`DungeonWorld.Strike`），盖着「先制攻击！」「遭遇！」或「被偷袭！」的印章，这时区域牌、小地图、状态和按键提示都收起来，到战斗结束回到迷宫再出现；战斗场数和先制、被偷袭的计数在演出之后才记。先制攻击（按 Enter 打没发现主角的噪声体）：主角转向它（0.1 秒），把手机伸到臂长拍照，0.28 秒时快门响，镜头前爆开一团闪光；没发现主角的噪声体在被拍下之前就被吓得离地弹起半米多，快门的闪光再把它打得往后一仰、方块震松，随后它定在半空，标题党型开始散成方块（别的类型抖散）；DeepSeek 觉醒之后举着饭勺跃过去劈下，没觉醒的校服 DeepSeek 打不了（她在剧本里说「我只会躲」），吓得蹲下。迎击（按 Enter 打已经追上来的噪声体，印章是「遭遇！」）是同样的拍照，只是追来的噪声体不会弹起，只被快门的闪光打退。遭遇（噪声体自己撞上来）：主角把手机举在眼前戒备，DeepSeek 拿着饭勺摆好架势。被偷袭（追上来的噪声体从背后撞上）：两人被撞得向前一仰，屏幕四边泛红，镜头震一下；撞来的噪声体在镜头这一侧时（不躲开它会挡满镜头），镜头先绕到另一侧、从两人的肩后看，在两个绕法里选能让 DeepSeek 留在画面里、又不被队伍卡片盖住的那一侧。没挨快门的噪声体（撞上来的、偷袭的，以及一起并入战斗的同伴）向主角扑去，扑到身子的前沿贴住主角为止，最远 0.6 米。镜头在这 0.75 秒里朝主角、噪声体和身边的 DeepSeek 的中点推近，视野收窄、往噪声体一侧歪 3°，印章盖在镜头推到位之后噪声体的头顶上方；头顶上没有位置时印章缩小，再不行就盖到噪声体旁边。战斗的转场盖住画面后，被拍到的噪声体被拿走；战斗结束后 DeepSeek 站回主角身边，镜头回到主角身后。「画面震动」关掉后镜头不歪、不震，推近缩到 0.4 倍；「减弱闪光」打开后被偷袭时的镜头震动也去掉，快门的闪光和屏幕边缘的红光压暗。

走、跑、冲刺和站着（`Editor/GaitMotions.cs`，菜单 **System Prompt → 生成行走跑步动作**）：四段都是 Quaternius 通用动作库的循环改出来的，原始循环在 `Editor/Motions/Gaits/`（`Walk_Loop`、`Sprint_Loop`、`Idle_Loop`）。动作库是按高个子男性做的，一米五几的角色照它的步幅跑，速度一快就只能二选一：脚打滑，或者一步跨两米多、一路三级跳。所以先把速度降到这个身高跑得出来的范围（`DungeonWorld`）：队伍跑动 4.6 米/秒、冲刺 6.6 米/秒（原来 6.2 和 9），加速度 31 米/秒²；噪声体跟着降，巡逻 1.7、返回 2.2、追击 3.8 米/秒，深层追击 4.8（比跑快，只有冲刺甩得掉），尾迹和水花的阈值一起降。跑步用库里的冲刺循环，往「跑」的方向收：前倾从 25° 立到约 14°（改前倾时大腿按原来的朝向转回去），背挺直，下巴抬起来（库里的人看着前面几米的跑道，放到这些角色上像埋着头跑）。库里的冲刺大腿最多前摆 75°、后摆 37°，每步落地还深蹲一下，放在跑步的速度上是从下蹲里一步步劈着叉跳出去：大腿的摆幅过了 42° 和 30° 1.1）：压低以后身体在踩地时最高、腾空时最低，脚贴着地面掠过去，起伏是反的，像在滑行。库里的手肘外张、拳头端在胸口，改成手肘收到身侧并多折一点（`ArmsIn`、`Elbows`；试过把摆幅和肘角放大，前臂每摆一下都伸到身前，像在划船）、手半张开（`Hands`）。库里的冲刺每一步胸和头都要前后点一下，头约 秒。手机是横躺在握拳的手上的（`SeaFigure.InHand`，站姿和截图都这么握），立起来要把手腕往旁边弯到关节转不到的位置，所以不立，只让亮着的屏幕朝向自己：胜利镜头在身后，过头顶的那块亮屏正好和道具里举起的饭团区分开。主角的手机在 0.45 秒时闪一下，快门声也在这一刻响（`Cheer` 返回快门的延迟，`BattleScreen.Victory` 在那一刻放音效）；还躺着的队员起身而不摆姿势，HP 为 0 的也不摆。

截图有快门时机（`BattleScreen.ScreenshotFx`）：取景框从 2.2 倍大小在 0.8 秒里匀速收到目标身上四个淡绿色的角上，合拢后再停 0.14 秒，框下写着「合拢的一瞬按 Enter：抓拍」。框缩到 1.1 倍以内时按 Enter（或点一下）是抓拍：取景框的角变白、盖一枚「抓拍！」，这一击必中并且暴击（`DamageCalc.Compute` 的 `snapped`），暴击照常击倒、给 One More；按早了当场拍一张普通截图，一直不按就在停留结束时自己拍下，也是普通截图。命中和伤害在快门按下的那一帧才算，所以抓拍不会撞上一个已经掷出来的 MISS。教学战斗不计时机，照旧直接拍。

灯塔脚下、影子说完「大家要的是答案，不是你」之后有一场打不赢的围攻战（`prologue_siege`，`BattleDef.Siege`）：主角一个人对标题党型 ×2 和转发型 ×1，谁都不会倒下（双方 HP 最低留 1），截过的噪声体在敌人回合开头「重组」回满血，每回合末再从人群里围上来一只（场上最多四只），全员倒地也不给集成（集成的收尾会去掉 HP 下限，等于赢了）。三回合后或主角 HP 降到 30% 以下，画面盖章「删不完……」，不进结算，掉的血也不带出战斗，剧情接着走到觉醒。第一、二回合开头各有一段提示（`BattleDef.TurnHints`，剧本里的 `Prologue_Siege_*` 节点）。开场就有三只以上的战斗（迷宫里合成的、围攻战）里转发型不再召唤，一场最多四只噪声体。

冷知识型是一叠微微错开的索引卡：浅色纸面画着蓝色横线和一道红色抬头线，格子一次只有几块烂成噪声的颜色，起疑和追赶时更多（`Glitch.shader` 的 `_Card` 模式；之前整张卡都是闪烁的格子，看上去像棋盘）。卡片右上方悬着一只故障灯泡：编造的数字越攒越多时越亮，过热时发红，偶尔闪一下，倒地时滚到一边变暗，被删除时往上飞走（`NoiseLook` 的 `bulb`）。卡片是扁的，战场上放大 1.2 倍，站后排时只往后退半步（0.6 米），不然在两团方块中间显得最小。

命中的手感由三样东西叠出来（`BattleStage` 的 `Freeze`、`Shake`、`Punch`）。一是顿帧：每一下打中，战场都停几帧，队员、噪声体和它们所有的位移都按战场自己的时钟走（游戏时间减去顿帧），顿帧里原地不动，镜头、海面和特效的光照常走，所以一击打在动作定住的那一刻，伤害数字、受击音和视野的收缩都落在接触的那一帧上。顿多久看分量：直拳 0.05 秒，横斩和回旋扫 0.07，交叉拳 0.08，跃劈 0.11，截图的快门 0.06，寒流的冰炸开 0.08、深海潜流的每块冰 0.04，扔出去的汽水和辣条 0.06，打中弱点或暴击再加 0.04，队员挨打 0.05，队员自己打出的最后一击 0.16。落空的不顿：伤害在出手之前就算好了（`DamageCalc.Compute`），落空的出手没有顿帧，也没有噪声体的击退。落空的也不出「对抗样本！」：原来扔偏的汽水和落空的法术只要对方弱这个属性，印章、碎裂声和震动照样出，画面上是 MISS 旁边盖着「对抗样本！」，弱点牌却没碎。顿帧不受「减弱闪光」和「画面震动」影响，因为它既不闪也不晃。二是晃动：镜头朝打来的反方向晃，画面顺着打击的方向被带出去再摆回，以 11 Hz 来回摆、越摆越小，带一点滚转和随时间淡掉的细抖；方向是打击在画面上的投影，直冲着镜头来或背着镜头去的，就往下沉一下；轻的晃动不会截断还没停的重的。晃动不抽 `UnityEngine.Random`，伤害判定共用它，晃动一抽就会改变同一个种子打出的暴击和落空。三是视野的收缩，顿帧里保持在最窄，顿帧过后才弹开。弱点、暴击、冰炸开、深海潜流爆开和跃劈落地时，画面还会从落点荡开一圈波纹（`SeaLens.Wave`，镜头后处理里的一道环带，最多三圈同时在外，每圈 0.4 秒，把环带上的画面往外推，最强时偏开画面高度的 3%，没有波纹时这一步不算，探索里没有）：界面、印章和数字画在它后面，不跟着弯；「画面震动」关掉就不荡，因为它会移动画面。「画面震动」关掉后不晃，收缩剩 0.4 倍，让一击仍有分量；「减弱闪光」打开后，战场上的闪光、星芒和冲击环压低亮度、封顶在白色以内，闪光也缩小，特效打在场上的光减半，集成的黑白剪影变得更慢（0.25 秒，平时 0.08 秒），只变到七成半。

队员自己出手打死最后一只噪声体时（集成不算；一个技能同时打死几只，算最后那只）有一段单独的镜头（`BattleStage.Finish`）：先顿 0.16 秒，顿到 0.1 秒时切到杀招机位——噪声体前方 4.2 米、偏到出手那人的另一侧 1.4 米、高 0.7 米，视角 44°、歪 8°，退到队员两米二以外——再用 0.9 秒朝它缓缓推近 0.35 米；崩解放慢到 0.75 秒（别的击杀是 0.55 秒），多一颗星芒和一条细光柱。胜利的镜头在这一击之后约 0.55 秒就接手，崩解的方块还在飞：方块飞出杀招机位的窄画面之后，镜头会对着空机柜停半秒，接手要赶在那之前。这一击紧跟着的余韵（技能 0.7 秒、扔道具 0.3 秒）在它赢下战斗时跳过，同样是为了不让镜头停在空机柜上；别的击杀，胜利要等崩解播完才开始。

战斗里的等待很短。队员的技能名条只是飘在画面上、不拦着出手（滑入 0.12 秒、停 0.45 秒、淡出 0.2 秒）；噪声体的技能名条只等名字进场（0.2 秒），其余的在它出手时淡出。技能和扔道具之后留一小拍让数字和崩解被看清，赢下战斗的那一击不留。队员全部行动完，先停 0.2 秒让最后一击的数字和收招演完，再滑入「敌人的回合」横幅，停 0.2 秒，滑出用 0.12 秒；滑出的同时第一只噪声体的镜头已经动起来。从最后一次普通攻击命中到那个镜头动起来约 0.8 秒（技能和扔道具再多上面说的那一拍）。倒地的噪声体在自己的回合起身，这一拍等 0.55 秒。

噪声体的反应（`SeaActors.cs` 的 `NoiseLook`、`NoiseRig`）。每只噪声体的身体挂在一组弹簧上：整个身体的位移和倾斜、沿正面压扁摊宽或拉长、伸出去的东西被打得缩进去，都是弹出去再弹回来，两个来回、约三分之一秒停下；带顿帧的一踢是直接弹到最远处停在那里，也就是只落在它一个身上的顿帧。被选作目标的噪声体睁大成琥珀色的眼睛，往后缩一小下。挨一下普通打击，它被朝打来的反方向踢出去，同时压扁、通体泛白闪一下（法术和道具闪的是属性的颜色）、一部分方块被震松、行列被撕开一点、眼睛眯成一条线；转发型的箭头被打得往里缩，冷知识型的卡片被打得散开一点，最上面的一张被翻过去。打中弱点或暴击倾得更斜、再随机扭一个角度、顿得更久，闪光是那一击的颜色，噪声体的彩色格子也换成那一击的色（冰蓝、火橙、暴击红、其余弱点绿），保持约四分之一秒，再一格一格还给它（一共 0.6 秒，整格换色，不出现两种颜色混成的脏色）。「减弱闪光」打开时噪声体的皮肤也平静下来：格子换色慢到四分之一、颜色互相靠近、不冒白格子、受击的闪光更淡、抖动减半。

战场上队员怎么站、朝哪边：三人的待机取自动作库的循环（`Editor/StancePoser.cs` 的 `Library`，菜单生成）。男女主角用同一条端枪的待机，双手把手机端在胸前，屈膝前倾（运行时由 `SeaFigure.Settle` 加上，见上文）；手机壳是浅色的，背面一颗带青色光圈的镜头（原来是深色的，端在深灰卫衣前面看不见）；女主角原来用施法的待机，两臂平伸在身前，从侧面看像梦游。DeepSeek 用施法的待机（镜像，伸出的是右手）：库里这条是侧着身站的，原样套上去髋转开 42°、胸转开 61°，从斜后方的战斗镜头看像背对着噪声体，所以 `Library` 每条有一个偏航角（她是 +28°），`Fitted` 把根的朝向和水平位移一起转回来，再用几条肌肉偏移把胸口摆正：现在她的髋偏 21°、胸偏 29°。这条待机原本右手举在胸前、掌心朝着噪声体，看着像招手或喊停；现在右手在运行时摆（`SeaFigure.Paddle`，`HoldPaddle`）：手放到腰前、肘垂在身侧，手腕伸直、拇指朝上，饭勺从掌心沿前臂指向噪声体，像拿着一把短刀。饭勺整场战斗都拿在手里，防御、道具、深度思考、施法和投掷时收起来（`HandsBusy`），做完再拿出来。主角端手机的手靠肌肉值摆不准，改成运行时摆：`SeaFigure.Ready`（`HoldReady`）把手机横着端在胸前（两肩中点往前 0.3 米、往下 0.2 米，上沿前倾 14°，手在 1.06 米高，肩在 1.32 米），两只手用 IK 握在机身上；出手、挨打和走动时这只姿势按比例让开，举起手机拍照（`HoldPhone`）从它起势。DeepSeek 近身出手后不再平移滑回去：`Dash` 的 `Back` 让她面朝噪声体向后跃回原位，起跳用 `Leap` 的 1.5 倍速，弧高 1.15 米、0.56 秒（离得近时 0.6 米、0.42 秒），空中后仰到 16°，落到 78% 时接 `Land`。勺头的光带只在出刀时拖：助跑和翻滚时不拖，跃劈从起跳就拖，跃回去时收掉；水做的刀锋（`BattleEffects.Swipe`）到出刀那一刻才建，采样点记在她身体的局部坐标里，她往前冲时刀锋跟着走，不会留在身后。集成的三趟冲刺里队员都面朝前进的方向、前倾 14°：主角是冲刺（`Sprint` 1.3 倍速），不再单膝横滑；DeepSeek 握着饭勺边冲边挥。这些朝向和姿势是用视觉实验室的 `poses.tsv` 按数字核对的（见[视觉实验室](#视觉实验室)）。

队员倒在海床上的样子：被弱点或暴击打倒（`Knock`，动作 `Knockback`）和 HP 归零倒下（`Faint`）都落到同一个瘫倒的姿势，起身（`GetUp`）从它开始。动作库里人倒下以后是笔直的：双腿并拢、手贴身侧、脸朝天，像一块木板。`Editor/BattleMotions.cs` 的 `Sprawl` 把两段倒地的最后 0.4 秒带到瘫倒的姿势（一条腿屈膝、两腿分开，一只手甩在身侧、另一只抬到头边，头偏向一侧），起身的头 0.4 秒从这个姿势放开；写的是肌肉的目标值而不是偏移，所以三段动作在同一个姿势上接得上（生成时日志里会列出每条肌肉从多少改到多少）。同一个瘫倒姿势在三副骨架上摆出来不一样，战斗服的一只前臂会立在肘上、手张着，像在招手：躺下以后（髋低于身高的三成）`SeaFigure.Rest` 把还举在空中的手放到地上，前臂绕肘转到贴地，方向沿它原来在地面上指的方向；手腕已经着地、手掌却立着的，把手掌按手指原来的朝向放平（只在倒地的姿势定住时做，起身时手臂交还给动作）。髋第一次落到离海床 0.3 米以内时，落点荡开一圈尘环、溅起几点光，镜头轻震一下；影子从脚下挪到躺着的身体下面、放大三分之一（倒地会把身体带离原位一步，原来影子留在脚站过的地方）。

被弱点或暴击打倒的噪声体躺在海床上：身体侧翻 70°、沉下去一点，弹一下，落地处荡开一圈尘环，整个暗下去，闪烁和动作慢下来，眼睛半闭着打转，头顶有一圈绕着转的方块，像一个在缓冲的圈；标题党型的弹窗往下耷拉缩小，转发型的箭头垂下去不动，冷知识型的卡片沿着躺着的身体摊开；屏幕上它的 2D 字样藏起来，只留一个 DOWN。起身是蹲、跳、落：头上的圈炸成像素，眼睛瞪成怒眼，先压低一拍（0.12 秒），再跳起 0.45 米（0.2 秒，身体拉长），落地压扁、左右晃两下。被打死的噪声体会被「删除」：最后一击把它定住、通体泛白，眼睛闪几下熄灭；接着它被撕开，炸成自己颜色的一团像素（里面夹着白的），一圈闪光和冲击波，头上弹出一个像弹窗的窗口写着「已删除」（冷知识型是「已辟谣」），张开 0.12 秒、停 0.3、像关窗口一样收掉；0.2 秒后方块各自翻着跟头、缩小，朝着打来的反方向飞散，从镜头旁边掠过、而不是撞进镜头，落在海床上变暗；它身上松脱的东西也飞出去：弹窗翻着飞走，转发型的箭头顺着各自指的方向射出，冷知识型的卡片像纸一样飘散下来。窗口开在身体上方；「对抗样本！」或「集成！」的印章占着那里时，窗口顺着画面往旁边滑，滑到印章实际占的那一块（对抗样本！按它落下的位置，集成！是画面上方中间的标题）之外，仍留在画面里。

噪声体出手前先蓄势（`BattleStage.Brace`，放在技能条滑进来的那段时间里，不另加等待）：朝要打的人的反方向退 0.35 米、压低、发抖、眼睛变红，标题党型的三张广告同时弹开、都写着「震惊！」，转发型的箭头拉长、转得更快，冷知识型把卡片像一手牌一样展开。扑击从蓄势的位置冲出去，撞上时正面压扁、顿一下，再弹回原位。砸出去的东西是从身体上离开的：弹窗就是它身上的那几张广告，箭从箭头的尖上射出，卡片从那一叠里甩出来，离开的部件 0.9 秒后长回来。战场上的噪声体有一张读得出的脸（地图上的还是原样）：眼睛放大、嵌在深色的眼窝里，上下眼皮和两根细亮条摆出平静、瞪圆、眯眼、「> <」和转圈的 X；标题党型多一张红唇的嘴，生气和挨打时张开，露出「震惊！」。站着的噪声体会朝正在行动的队员转过去一点（最多 20°）。身边的 2D 喊话一次只出一句，被瞄准和倒地时收起。全员倒地、等玩家决定要不要集成的那段时间里，倒地的噪声体缩成「> <」的眼睛、发着抖求饶（`BattleStage.Cower`）：标题党型的广告换成「求放过」「别删我」「我错了」「下次一定改」，冷知识型的卡片写着「其实…」「我编的」「求别辟谣」。技能切入的色带里是 DeepSeek 的一双眼睛（立绘上眼睛在 23% 的高度，取高了色带里只有刘海）。

战斗界面：右下是队伍卡片，头像从卡片上缘探出、略歪，都是 2D 图：主角按性别用家居服半身像（`Resources/Art/Portraits/player_male.png`、`player_female.png`，原图在 `assets/characters/protagonist-card/`，只在战斗卡片和结算里出现（单人战的结算立绘也用这张），剧情不显示主角的脸），DeepSeek 用战斗服立绘。头像会演表情（`UI/Battle/BattleViews.cs` 的 `CardFace`）：出手时（普通攻击、技能、集成）皱眉、瞪眼、吸气、咬牙蓄力，喊出来并往前一冲、再喊一遍，喘口气，冷笑一下再平静下来；挨打时一愣、闪红，缩起来痛叫、被打歪，疼劲过去后先睁一只眼再睁两只，喘口气瞪回去再吐口气；胜利时在结算盖住卡片前先松口气、睁眼笑出来，结算栏里的头像接着循环哈哈大笑、得意、眨眼、挤眼和咧嘴笑。每种表情 12 张手绘，都是拿原立绘让图像模型只改表情重画的，和原图逐像素对齐；相邻两张渐变过去的地方，再用 ffmpeg 的运动补偿插帧（`minterpolate`）补 2 张过渡帧，只有挨打的那一下直接切。帧按头像窗口裁出（立绘上 554 像素见方，比窗口宽三成，抖动和前冲不露边），铺上卡片底色存成 384 像素的 JPG（`Resources/Art/Portraits/Card/`，每人 37 张原画加 88 张过渡帧，过渡帧命名为 `<起>-<止>-1`、`-2`）。换帧之外，头像全程跟着动作动：攻击时发抖、往前冲，挨打时被打歪、回弹、泛红，胜利时上下晃、左右摆、跳一下。GIF 预览在 [assets/characters/battle-faces/](../assets/characters/battle-faces/)。名字贴在白纸条上，HP 和 SP 是大号数字加血条，HP 降到三成以下变红。轮到谁行动，谁的卡片就上浮、描绿边、挂「行动中」标签。左侧的指令菜单逐行向右错开，每项右边有英文小标（ATTACK、SKILL、THINK、GUARD、ITEM），底下有按键提示。技能和道具列表在指令菜单原来的位置打开，不挡住站在它右边的当前队员。噪声体头上的名牌收窄了，被瞄准时翻成白底并略放大。有人出手时，噪声体的名牌、弱点标签和身边的 2D 字样淡出（只动透明度，位置照钉），把画面让给身体和特效；选指令、选目标、全员倒地的提示和每回合开头再淡入，倒地的 DOWN 标签一直留着，只有集成时也收起；出手时新叫来的噪声体名牌从一开始就是收起的。出手的队员打中谁，谁的名牌亮 0.8 秒。HP 条被打掉的部分马上变红缩短，后面拖着一截白条，过 0.25 秒再追上来（回复时两条一起涨）。伤害数字钉在被打中的东西上（`BattleFx.Popup`）：噪声体身上的数字跟着它的身体走，它倒地时名牌往下掉，数字也跟着掉，停在名牌下面、DOWN 上面；队员身上的数字停在挨打的位置，被镜头推出画面就先藏起来，队员根本不在画面里时落在他的卡片上。数字一个字一个字砸出来，每个字歪几度；噪声体受的是纸色，队员受的是红色，回复是绿色，MISS 是灰色；弱点和暴击的数字更大，垫着一团对应颜色的爆炸框，上面斜着贴 WEAK 或 CRITICAL；同一个人身上同时有几个数字就一个叠一个，每个高 70 像素。一个数字砸出来用 0.12 秒加每个字 0.03 秒，停 0.45 秒，再往上飘 40 像素、淡出 0.2 秒。技能或扔出去的道具打中弱点时，在打中之后 0.16 秒压一枚「对抗样本！」印章（`BattleScreen.WeakStamp`）：先让人看见这一击，再盖章。它盖在画面上远离所有被打中的噪声体的那一侧（印章靠近噪声体的一边，离它们的中心至少 180 像素，往中间歪 8° 到 10°，两侧一样宽时靠右），从 1.35 倍落下，比别的印章落得近，因为它要落在动作旁边，不是盖在动作上；停 1.1 秒就收，不拦着后面的动作。ONE MORE! 出来时先把它收掉，自己挑位置（`BattleScreen.OneMoreSpot`）：先看「对抗样本！」那一处，如果会盖住倒地的噪声体、它的名牌或 DOWN，或它的身体（`BattleStage.FoeOnScreen` 把身体的包围盒投影到屏幕上；倒地的身体在近景里躺得离名牌很远，可以占半个画面），就在整幅画面上 9×3 个位置（高度 380、220、560）里挑盖住最少的，差不多一样空就挑离第一处最近的；落下的起点不大于离画面边缘的余地允许的倍数（1 到 2.4 倍），所以印章不会被画面边缘切掉。

战斗规则（`UI/Battle/BattleScreen.cs`）：标题党型头上的「弱点：火」是假的，每场战斗第二回合碎掉露出真弱点；在那之前用冰打中它也会当场揭穿。打中过弱点或耐性，名牌上就记下（「弱点：冰　耐性：火」），之后选目标时名牌上方斜着贴出 WEAK、RESIST 或 BLOCK，没摸清的属性不提示。冰镇汽水和辣条是攻击道具，扔向一个敌人，冰或火属性，威力 30，同样能打出弱点和 One More。转发型不在教学战斗里时，会隔一回合把一只标题党型「转发到十个群」叫进战场（光从它身上射到空位，炸开像素长出来），一场最多叫两只、场上最多三只；叫来的标题党型 HP 16，打倒加 10 EXP。每个队员记得上次打的目标，下次选目标时光标先停在它身上（它倒地了就不停）；没有记着的就停在第一个没倒地的，给队员用道具选目标时同样，躺着的队员不会被默认选中。

深层出口旁的白门在剧情里会变成镜子（`Dungeon/SeaMirror.cs`）：一台反射相机从镜面的另一侧拍场景，镜面从中间一圈波纹往外铺开、带一道亮环，镜子里的主角换成还没觉醒的战斗形态（5-battle）；结束时一道光带从上往下扫过镜面，扫过的地方倒影变回主角现在的样子（原来的一下白闪占了大半个画面，没有了）。变镜子之前，「我走到门前」那一句时两人先小跑到门前站定（`<<mirror walk>>`，`DungeonWorld.MirrorWalk`）：主角站在镜面中线左边一米，DeepSeek 跟着一起走到右边自己的位置（`SeaCompanion.WalkTo`），不是被摆过去的；这段不算迷宫里的一步，维护进度不动，按确定、取消或按住快进后三倍速走完。镜头跟到最后几米时绕到两人身后，门前的雾跟着淡掉，否则被门照亮的雾会把下半幅画面洗白，镜子一出现又在一帧里消失。定格的镜头退到镜面前 4.1 米，门两侧的壁柱留在画面边上，读得出是门上的一面镜子而不是一扇窗。「减弱闪光」打开时亮环和光带减半。反射画面按整个窗口的分辨率渲染、开当前画质档的 MSAA：镜子里的人站在真主角身旁，糊一点或边缘有台阶都会被一眼看出来。镜子打开期间每帧要多渲一遍场景，开销是整幅画面的。

两张地图各有一个机关。浅层维护间：站在缓存块后面按 Enter 往前推一格，三块都推进插槽后，橘色的门打开，门后是维护终端；推进死角时按复位台。最少要 19 推：紧挨插槽的那块西边是矮墙，推不进去，得先往北推开让路，顺手往南推的话会贴死在南墙上（布局用一个推箱子求解器筛过：只有少数几处放第三块还解得开，选了最少推数最多、第一推里死路最多的一处；后来发现原先东北角那块 (25,12) 正好挡在入口看插槽的视线上，进门时镜头转向插槽也看不见，就用同一个求解器把它挪到 (21,12)：不在那条视线上，最少推数从 17 变成 19）。缓存块是一人高的方块，深色外壳、浅色框架、发光的角，四面是存储单元面板，浮在自己的光上，推的时候先往后一仰，停下时晃一下；插槽是一块深色底座，橘色的边框和朝里的箭头，上面立着一个缓存块的线框，有扫描线往上走，推进去后线框消失，底座、边框和块一起变绿。深层白门大厅：灯塔的光从裂缝照进大厅，六块反射板每按一次转 45 度，把光引到门边的空地上，出口才出现。光有两条路可走：东边经过 (17,6)、(17,3)、(11,3)，转 3 次（(17,6) 一开始就是对的）；或者往西经过西墙下 (9,6)、(9,2)，转 5 次，但顺路捡到西墙的数据珍珠（+5 SP，深层 DeepSeek 的 SP 不够用）。中间那块 (14,6) 一开始和光平行，好让光先照在白门上，所以西路最多只能是 5 转；每转一次维护进度 +1%（`DungeonScreen.TurnPercent`），解法由 `DungeonDef.Plates` 的初始朝向决定。反射板是叉架上的一面深色玻璃镜，镜面有流动的反光，底座上的刻度盘指明转向；光柱从高处落到裂缝里的棱镜上，光束有白色的芯和顺着光走的条纹，照到的反射板变亮、在落点闪光。小地图上画着插槽、缓存块、反射板和光路。两个机关都能反悔：按 Backspace（手柄 B）撤回上一次推动，或把身边的反射板逆时针转回 45 度；缓存块推进两面墙夹住的角落、再也推不出来时变成红色，DeepSeek 提醒去按复位台。

探索里发生在视线之外的事用镜头交代（`UI/Dungeon/DungeonScreen.cs` 的 `Cutaway`，机位由 `DungeonWorld.FindShot` 找，离两人至少 2.5 米、不从正面拍脸）：最后一块缓存块推进插槽时，门不在画面里就切过去看它 1.6 秒（十八米以外、或者只在画面边上贴着小地图露一条，都算看不见）；终端的节点里用两个镜头交代两道防火墙解除（共 3.1 秒，先近的一道，第二道背后是灯塔）；反射板转对之后，光沿着光路一段段跑到出口，光到了，出口的光柱才在一个 1.8 秒的镜头里升起来。镜头上下各压一条黑边，界面收起，硬切进出；开始 0.2 秒后按确定、取消或按住快进，剩下的三倍速播完。状态（防火墙已开、光已照到、门已开）仍在原来的那一刻改变，只有画面晚一点；DeepSeek 的播报在镜头之后、回到探索时才出，所以播报照旧不打断探索；那一刻正在战斗或对话，就等回到探索再决定切不切。防火墙和门是溶解掉的（`Resources/Shaders/Dissolve.shader`）：先洗成白，再碎成一格格带亮边的方块，绿色的扫描线沿墙往上走，像素往上飘，海床上荡开一圈光环（`Dungeon/SeaGlims.cs`：事件的光借战斗特效打光的那条通道落在场景上，总量封顶 0.6，`Seabed.shader` 的 `_SeaPulse` 画光环；粒子都从 `SeaWake` 的池里发）。终端的屏幕滚着日志，节点播放时滚得快，一道光束往上打，防火墙的光束往下应。缓存块推进插槽时落座弹一下，一颗火花沿线缆跑向门；推不动时撞上去、泛红回弹。宝箱的盖子先往下压一下再弹开，开过头又回落，盖子掀起之后金色的光束、光点和三张卡片才从箱里升起，镜头朝它偏一下。走进出口离开时，浅层是灯塔的两道光转下来照在两人身上，深层是两人脚下升起一根光柱（`Dungeon/SeaColumn.cs`），这段时间界面收起。维护进度走满时，远处的机柜先暗下去、气泡往上涌，黑场 2.5 秒，再被弹回信标前，面朝信标。主角脚下的那圈光会呼吸，冲刺时放大，被噪声体追着时偏红。「减弱闪光」打开时，弹回的闪光峰值从 0.8 降到 0.25，事件的光和信标休息时的闪光减半。

两张地图各藏着五颗数据珍珠（`Dungeon/SeaPearl.cs`）：海床上一只张开的扇贝，里面浮着一颗发光的珍珠，头上一道细光柱，远处就能看见。走过去自动捡起：珍珠从壳里升起，沿一道弧线用半秒飞进主角的胸口，越飞越小，进了胸口以后只剩那一团光晕涨开、闪一下就没了（0.75 秒后收走），DeepSeek 摇一下尾巴；珍珠离镜头近时会淡出（0.8 米内看不见，2.5 米外才完整），免得镜头在窄走廊里贴上来时，一颗发光的珍珠糊满画面。捡起后全队 SP +5，左上角区域名下显示「◆ 数据珍珠 n/5」，小地图上标粉点；捡齐一张地图有奖励（浅层冰镇汽水 ×2、200 token，深层辣条 ×2、300 token），手机的资料页记着总数。深层的五颗都在两条路共用的区域，走哪条路都捡得齐。

门打开、出口出现、维护进度到 80%、第一次被偷袭这类消息由 DeepSeek 在右上角播报，像《女神异闻录5》的领航员（`UI/Dungeon/NavCall.cs`）：小地图左边甩进一个歪斜的头像框和对话气泡。头像框里是导航专用的半身立绘（`Resources/Art/Portraits/deepseek_nav_*`，从 [assets/characters/deepseek-nav/](../assets/characters/deepseek-nav/) 的原图裁出头肩和手），她手拢在嘴边朝左喊话；便服（浅层）和战斗服（深层，觉醒之后）各有笑、平静、惊慌、嘟嘴四种表情，跟着台词的 `#face` 换，没标的沿用上一句。台词打完停一会儿换下一句，说完滑出去；玩家照常走动，场景里的 DeepSeek 跟着动嘴。对话框出现或进入战斗时播报先让开，结束后接着说。

剧情画面右上角是一排 P5 风格的图标徽章（自动、快进、回看、存档、读档、手机、设置、隐藏界面、菜单），独立于对话框，可以直接点。徽章歪斜错落，角上贴着对应按键（Q、F、L、Tab、H、Esc）；鼠标停在上面时徽章放大、图标变绿，下方弹出名称；自动和快进开启时徽章亮成绿色，手机有未读时变红。日程期限卡在图标下面。标题画面和手机资料页的立绘可以点头和身体，连点太多次会有专门的反应。标题画面上，三个人的视线会跟着鼠标走。标题上的对话气泡浮在所有立绘之上、三人头顶之间的天空处，尾巴指向说话的人；同一时间只有一个人说话，点了另一个人，前一个人的气泡收起、表情复原。

标题的游戏名是单行字标：白色 SYSTEM，后面是歪贴在绿色色块上的黑字 PROMPT，末尾一个闪烁的终端下划线光标。开场时 SYSTEM 从左滑入，PROMPT 色块随着重音砸下来。

## 端到端验证

```bash
game/Tools/e2e.sh
```

脚本先用 batchmode 构建一个测试版播放器，再启动它。测试版产品名是 System Prompt E2E，存档和设置与正式版分开，每次都从空存档开始。启动后，`Assets/SystemPrompt/E2E/PrologueRun.cs` 用虚拟键盘从标题玩到序章结束，沿途经过：

- 标题画面、立绘动态特写、依次点三人的头（核对只剩一个气泡），以及设置
- 陪伴生登记和序章剧情
- 手机、暂停菜单（从菜单进回看、进存档）、回看和快速存档
- 缓存海·浅层探索（DeepSeek 穿便服跟在身边）：从背后攻击礁石出口发呆的噪声体（先制攻击，第一场单人战斗）、点亮信标、珊瑚林、墓地和峡谷各打一场、读墓地的草稿碎片、捡浅层五颗数据珍珠（核对奖励）、第三场战斗扔冰镇汽水打标题党型（核对选目标时不显示没摸清的属性、揭穿假弱点；命中是随机的，扔偏了下一回合再扔一瓶，手里的两瓶都扔偏时这一项验证不到，报告里会写明是汽水全扔偏了，重跑即可）、最后一场（机柜峡谷）故意迎面走过去、站着让噪声体看见追上，打一场被偷袭的战斗（报告核对开场是被偷袭，并写出主角最低 HP 和敌人出手次数，对照试玩文档「浅层至少一场主角低于 50%」），转发型叫来标题党型（这场里转发型叫人之前，主角只截图打标题党型，标题党型没了就防御，等转发型叫来一只再用第一个指令打完，`PrologueRun.cs` 的 `SpareTheCaller`：先制的那一轮里截图一暴击，旁边的标题党型倒下、One More 又打掉大半个转发型，它就来不及出手叫人，核对会落空，所以不靠这种运气；也不从第一回合就防御，那样标题党型一直站着，叫来的再加进来，主角要一个人对三只）、在维护间推 17 次把三块缓存块推进插槽、打开门（中途按 Backspace 撤回一次再推回去，核对插槽全满，DeepSeek 在右上角播报「门开了！」时仍在探索）、接入终端解除防火墙、穿过两道防火墙走到灯塔，核对战斗场数和走过的区域数
- 配乐：驱动每帧记下正在放的曲子和它第一次响起时游戏在哪，序章结束时核对八首都放过，「影子」和「深渊之鲸」是在灯塔脚下的剧情里响起的，「缓存海·深层」在深层探索里，「结算」在战斗里
- 三处过场 CG：潜入、深渊之鲸、学生会室的窗前各录一张胶片（片段放出几帧后开始，8 帧、间隔 0.9 秒，从片段开头录到停住），序章结束时核对三处都放出了动态片段、学生会室那张留到了最后
- 教学战斗（核对 3D 战场和钉在噪声体上的名牌）和 Coop 卡片
- 缓存海·深层探索：从背后攻击发呆的噪声体（先制攻击）、走东边的长上下文回廊读碎片、开宝箱（延时补丁让维护进度下降）、捡深层第一颗珍珠、在白门大厅转动四块反射板把光引到出口（最后一块按 Backspace 逆时针转一次，核对出口出现，右上角播报「出口出现了！」）、走到出口（白门变成镜子，截图镜中的战斗形态）
- 回到标题后打开读档
- 在标题上直接播一次战斗失败的转场（流程里不会输）；再把关机转场完整播一次、中途按确定播一次，核对按确定后用时明显缩短（机器忙时帧率会掉，所以和同一时刻的完整用时比）

运行期间真实鼠标会被屏蔽，只用虚拟键盘操作，免得桌面上停在窗口里的鼠标悬停改掉选中项。潜空间里按最短路径逐格按住移动键，遇到巡逻就转身攻击，战斗里一直按 Enter 用第一个指令打第一个目标；DeepSeek 入队后（`PrologueRun.cs` 的 `SmartCommand`）HP 不到四成的人吃白米饭，对面站着两只以上时她按 SP 出招：够 8 点放深海潜流，够 4 点放寒流打第一只，再不够才用饭勺；只剩一只时用不花 SP 的饭勺。饭勺的四种出手（横斩、回旋扫、鱼跃连击、跃劈）每种都要她普通攻击一次才拍得到，而深海潜流常常提前把深层的战斗打完，一局里她可能只出手三次、跃劈那张必拍的胶片就落空；所以深海潜流拍到之后、跃劈拍到之前，对面只有两只时她不放技能（三只以上照放）。每个界面和演出都会截图，同时核对游戏状态（等级、道具、Coop、期限、通讯录），并检查日志里有没有报错。画面切换（启动、开始游戏、换场景、进入战斗、战斗结束、潜入和离开潜空间、序章结束回标题、战斗失败）、暂停菜单展开、从菜单进入回看和退回菜单、设置开机、登记界面打开、存档快门、战斗结算和战场上各技能与攻击的特效录成胶片：一张图里 8 到 24 帧，按固定间隔从左到右、从上到下排列。标题立绘另录一张 20 帧的半尺寸脸部特写（间隔 0.1 秒），用来看呼吸、摆头、头发和眨眼。队伍卡片的攻击、受击和胜利表情各录一张只拍卡片那一条的胶片。结果写到 `game/E2E/<时间>/`：报告是 `report.md`（末尾的「战斗难度」表逐场列出回合数、敌人出手次数、每人最低 HP 和 SP、各指令次数，对照 `design/prologue-playtest.md` 的目标），旁边是截图、`build.log` 和 `player.log`。全部检查通过时退出码为 0。

查运行时的短暂卡顿用卡顿探针（`Assets/SystemPrompt/E2E/HitchProbe.cs`）：带 `-development` 构建测试版（`Unity -batchmode ... -executeMethod SystemPrompt.EditorTools.BuildTools.BuildE2E -development -buildOutput <app>`），启动时在 `-e2e <目录>` 之外再加 `-hitches <目录>/hitches.tsv`。探针给所有计时的 Profiler 标记各挂一个记录器，墙上时间超过 40 ms 的帧写一行：时间、帧号、用时、GC 次数、场合（标题、剧情、潜空间、战斗和曲目）和这一帧里用时最多的标记。挂了全部标记的开发版本身就慢（中位帧约 60 ms），所以看的是具体标记（`CreateGpuProgram`、`FontEngine.GetPairAdjustmentRecords`、`SoundManager.LoadFMODSound`、`Loading.ReadObject`、`GC.Collect` 这类）在多少帧里超过十几毫秒，改动前后各跑一遍比。正常的端到端验证不带这两个参数。

运行期间会弹出一个 1600×900 的窗口，不要碰键盘鼠标。窗口被别的窗口盖住时，系统会降低它的显示频率；开着垂直同步时游戏仍把每一帧算成 1/60 秒，整局变成慢动作，跑到整体超时。所以驱动让测试版不开垂直同步、按 60 帧上限走（`PrologueRun.Update` 每帧保持，游戏的设置一应用就会把垂直同步改回去），被拖慢的一帧算它实际用掉的时间，视觉实验室也是这样跑的。编辑器按 `ProjectVersion.txt` 的版本在 Unity Hub 的安装目录里找，找不到时用 `UNITY=/path/to/Unity game/Tools/e2e.sh` 指定。也可以在编辑器菜单 **System Prompt → 构建端到端测试版** 只做构建。驱动代码只编进编辑器和带 `SP_E2E` 定义的测试版，正式构建里没有。

## 视觉实验室

```bash
game/Tools/lab.sh [场景 id 或前缀 ...] [--no-build] [--out 目录]
```

端到端验证看流程有没有走通，视觉实验室看画面变成了什么样：改过角色动作、特效或场景的人，用它在改动前后各拍一遍同样的场景，对着胶片比。`Tools/lab.sh` 先用和端到端同一个 `BuildE2E` 构建测试版（产物是 `Builds/E2E/SystemPromptLab.app`），再带 `-lab` 启动；`Assets/SystemPrompt/E2E/VisualLab.cs` 在游戏里摆出一百二十多个场景，按固定的游戏时间间隔拍成胶片。场景分三族：战斗（`battle-`，分 `battle-main`、`battle-finale`、`battle-female` 三组：男女主角和 DeepSeek 的待机，三种截图和四套饭勺，寒流、深海潜流、道具、防御、深度思考，噪声体的扑击、召唤和各种出手，弱点、暴击、噪声体倒地起身、队员被击倒和倒下、被删除、最后一击、集成和胜利）、浅层（`sea-`）和深层（`deep-`，两张地图各有区域静帧、站立、走、跑、冲刺、步态近景（`-gait`：慢走、跑、冲刺匀速时各 1.6 秒，2.6 米外跟拍主角的侧面、身后和斜前方，以及同伴的侧面和身后）、模型近景（`-model`：两个人物站着各拍 13 张整窗静帧——正面、斜前、侧面、背面、斜后、半身、脸、斜脸、后脑、两只手、腿和脚——再加跑动中的正面、侧面和背面）、掉头、刹停、跑圈、同伴跟随、互相看、尾巴、脚印，噪声体的察觉、先制、迎击、遭遇和被偷袭，珍珠、信标、宝箱、机关和白门的镜子；浅层另有一块布景的场景，灯塔的光扫过地面和机柜（`sea-sweep`）、几处地标的近景（`sea-sights`：手机、珊瑚林入口、墓地、峡谷的墙脚和垂缆、广场）、珊瑚和海草摇摆（`sea-sway`），还有人背靠机柜走开再退回、看镜头在贴墙和开阔两种取景之间有没有跳动（`sea-wall`））。另有一族 `girl`，有 `girl-gait` 和 `girl-model`：女主角在浅层的站立、步态近景和模型近景（其余探索场景都是男主角拍的）。战斗待机（`battle-stance-*`）在胶片之外另拍四张整窗近景：前方全身、双手和手里的东西、脸、身后。倒下（`battle-faint`）另拍一张正对着脸的特写，并把舞台让她摆的表情格记进备注（闭眼是 0）：远看分不清眼睛是睁是闭。跨区域的 `-border` 不按固定时间跑，而是跑到主角进了下一个区域、再给水色和雾 2.6 秒缓过来；主角的侧面近景从同伴不在的那一侧拍。完整的场景表和每个场景拍什么，在 `VisualLab.cs` 开头的 `Def(...)` 里。

参数：不带参数跑全部（约 11 分钟）；写一族的名字（`lab.sh battle`）、一组的名字，或场景 id 的前缀（`lab.sh battle-shot sea-run`，空格分开），只跑选中的；`--no-build` 不重新构建，用上次的 `SystemPromptLab.app`（没有这个 app 时先不带它跑一次）；`--out` 指定输出目录，目录里旧的 png、`index.md` 和日志会先删掉。构建约 2 到 4 分钟（`Library` 已有缓存时），一族约 1.5 分钟，单个战斗场景约 40 秒。构建加全部场景可能超过 10 分钟，在会被 10 分钟超时杀掉的环境里，先 `lab.sh <一个小场景>` 构建，再 `lab.sh --no-build` 跑全部，或放到后台跑；整体超过 1200 秒时后面的组不跑，`index.md` 里记一条错误。从别的 git 检出（worktree）里调用主检出的脚本时，构建和拍摄的是那个检出的代码，缺的实验室文件、`Library` 和不进仓库的文件从本检出补上；`LAB_GAME=<game 目录>` 可以直接指定要拍的工程。

输出在 `game/E2E/lab-<时间>/`（`--out` 另指定）：`poses.tsv` 是每一帧里每个人物的姿势，一行一个人物：游戏时间、场景 id、人物、位置，根、髋、胸、头相对前进方向（站着时相对战场正前方）的朝向角，两脚和髋的高度、前倾和侧倾角、头高，两手的高度、两臂的朝向角、手伸出身体的距离和肩高，以及两只脚踝在世界里的水平位置（踩在地上的脚不该动，由它算得出脚底打滑多少）。人物朝哪、手举多高这类问题按这些数字比，不靠在 480×270 的胶片上目测（比如同伴跟随时根的朝向和前进方向的夹角：修之前平均 50° 到 97°，她侧着身横着走；修之后 2° 到 3°）。其余是画面：倒地的两个场景另有两张整窗静帧（`battle-knock-lying`、`battle-faint-lying` 和各自的 `-side`），从脚边上方和侧面看躺着的姿势。每个场景的 PNG 胶片（每帧 480×270，一行 4 帧，从左到右、从上到下读，每张最多 16 帧，帧间隔因场景而异）和整窗大小的静帧，`index.md`（每个场景拍了什么、间隔多少、期间记到的错误和警告，没拍到或失败的场景），还有 `player.log` 和 `build.log`；脚本最后一行打印这个目录。退出码为 0 表示选中的场景全部拍到、没有错误日志。游戏按真实时间跑，限 60 帧一秒，胶片的每一帧取在时间点上或之后最近的一帧，所以两次运行的帧最多差半帧。游戏状态只在内存里：脚本把 `HOME` 指向一个临时文件夹，实验室发现游戏的数据目录不在里面就拒绝启动，真正的存档和设置不读、不写、不删；设置是默认值（画面震动开、减弱闪光关、静音）。战斗走 `GameRoot.RunBattle` 和键盘，正常流程里看不到的（冷知识型的「你知道吗？」、单独的扑击、指定的弱点或暴击、队员倒下）直接在战场上摆；实验室为此读写游戏的一些私有成员，改名或重构它们时要同步改 `VisualLab.cs`。运行期间会弹出一个 1600×900 的窗口，不要碰键盘鼠标；实验室只响应自己的虚拟键盘和手柄，桌面上的设备被屏蔽。

同一个仓库的所有检出共用一把锁（git 公共目录下的 `sp-lab.lock`），一次只有一个实验室在构建或运行，所以几个人同时调用会轮流等，被占着时最多等 60 分钟，每 30 秒报一次是谁占着，持有者的进程不在了就清掉失效的锁。`e2e.sh` 取的是同一把锁：实验室和端到端验证都用 batchmode 构建同一个工程、都弹出窗口并用虚拟输入操作，同时跑会互相拖慢到超时，所以两边轮流。自己另开 Unity batchmode（转换动作、重新生成站姿）时不经过这把锁，要错开。`VisualLab.cs` 和 `PrologueRun.cs` 一样只编进编辑器和带 `SP_E2E` 定义的测试版，正式构建里没有，只在带 `-lab` 参数启动时才运行。

## 正式版构建

```bash
game/Tools/release.sh
```

用 batchmode 构建 macOS 和 Windows 两个正式版，各打成一个 zip，用来上传 itch.io 这类平台：`game/Builds/Release/SystemPrompt-<版本>-macOS.zip` 和 `-Windows.zip`，版本取 Player Settings 的 Version。只打一个平台时写 `release.sh mac` 或 `release.sh win`。编辑器菜单 **System Prompt → 构建正式版** 下也有这两项，只构建不打包。

正式版不带 `SP_E2E`，端到端驱动、视觉实验室和录像都不编进去，窗口失去焦点时游戏暂停。macOS 版同时包含 Intel 和 Apple Silicon。Windows 版要先在 Unity Hub 里给 6000.0.85f1 加 Windows Build Support (Mono)，Mac 上就能直接打；没装时脚本停下来，并提示缺哪个模块。Windows 版是一整个文件夹（`System Prompt.exe`、`UnityPlayer.dll`、`System Prompt_Data`、`MonoBleedingEdge`），要整个打包。

正式版的公司名是 `System Prompt`，Bundle ID 是 `com.systemprompt.game`（`BuildTools.ReleaseIdentity`），只在构建期间写进 Player Settings，构建完就改回去。存档和设置的位置由这两个值决定：macOS 是 `~/Library/Application Support/com.systemprompt.game`，Windows 是 `%USERPROFILE%\AppData\LocalLow\System Prompt\System Prompt`。已经发布，就不能再改，否则玩家的旧存档会读不到。工程本身仍然用 Unity 默认生成的标识，所以测试版还是 `com.DefaultCompany.System-Prompt-E2E`。`e2e.sh` 每次运行前都会清空这个目录，但碰不到正式版的存档。

macOS 版没有签名和公证。从网上下载的 zip 解压后，系统会提示应用「已损坏」或无法验证开发者。玩家可以右键选「打开」，或者在终端运行 `xattr -cr "/Applications/System Prompt.app"`。不想让玩家多这一步，就要用 Apple 开发者账号的 Developer ID Application 证书签名，再用 `notarytool` 公证。

画面切换参照 P 系列，在 `UI/Elements/Transitions.cs`。所有转场用同一套做法：要离开的画面先截下来，用滤镜打碎（色差、整行横向撕裂、像素块、缩放模糊、显像管关机）；盖住时是墨色底上一张生成的背景图，加扫描线和红青色差的大字；揭开时盖板带着发光的边退开。现实里用 P5 的斜切，进出潜空间是潜入数据海、浮出终端，战斗是碎玻璃，输了是信号中断，章节结束像关掉显像管，开机和回到标题都从雪花屏里解码出来：

- 启动：雪花屏盖着标题，雪花底下隐约是电路板，电流一圈圈往外扩；随后按随机方块一块块解码出标题，方块边缘亮绿。
- 标题和剧情之间、读档、战斗结束：一列斜切色块从左扫过，扫过时旧画面褪色、色差分开、整行横向撕裂；盖住后是斜着滑过的电路板，底下还有一层更细、更慢的电路板；光点沿着走线跑，一圈圈电流从中心往外扩，点亮经过的走线，数据小方块往上飘；右下是加载条、一行终端日志和放大的 NOW LOADING。
- 剧情换场景：同样的斜切，中间停下显示地点卡；地点卡下面开一扇窗，目的地的背景从马赛克和雪花里解码清楚。
- 进入战斗：探索画面被吸进爆炸框（缩放模糊、色差、变蓝），爆炸框炸开后，碎玻璃不停地迎面飞过，速度线从中心射出，光带横扫过去，ENCOUNTER 色差抖动着砸下来，再沿对角线裂成两半退出。
- 进入潜空间：剧情画面变蓝、碎成像素块一块块熄灭，露出一段沿数据海的井往下坠的视频：聊天气泡、数据面板和气泡迎面冲过去，代码流沿井壁盘旋，光环一圈圈掠过，井底一点冷白光；上面再叠速度线和往上飞的数据块；DIVE 砸下来，下面是 LATENT SPACE // CONNECTING、区域名和往下跳的深度计。潜空间场景在这段时间里搭好，没搭完时井一直往下坠、停在 DIVE 上。最后接着往下坠出井底：文字散开，井加速冲过去，从中心打开一个边缘柔和发光的圆环，露出 3D 场景，镜头同时从主角头顶高处转着降到身后，中间没有闪白和硬切。
- 离开潜空间：3D 画面褪成绿色荧光、从下往上抹掉，露出按列往下落的终端日志：每列速度不同，列头亮、拖尾渐暗（像在往上浮），SURFACE 和回升的深度计，再被一道绿线从上往下扫掉。
- 战斗失败：「掉线……」之后画面整片撕裂，红青色差、雪花和故障画面闪烁，打出 SIGNAL LOST，接着像显像管关机一样压成一条亮线、缩成一点，黑屏后从雪花里解码出标题。
- 序章结束回标题、在标题选退出：显像管关机；回标题时同样从雪花里解码。

切换期间不接受输入。开始 0.2 秒后按确定或取消，剩下的部分三倍速播完、中间的停顿取消。一帧卡得再久也只按 0.1 秒推进，不会让动画直接跳到结尾。潜入时潜空间场景在后台搭：先用 `Resources.LoadAsync` 读入场景模型和两个角色，再每帧搭一块（场景模型的每个文件用 `InstantiateAsync` 分几帧复制进来，再分帧整理和合批，然后是海床、区域装饰、灯塔、道具、残骸、机关和两个角色），3D 镜头在揭开前一直关着，所以潜入视频不会停。场景文字用的旧版 `TextMesh` 第一次创建要半秒，开机第一帧之前先建一个。设置 → 辅助里打开「减弱闪光」时不做横向撕裂和抖动，闪光也减弱。快进剧情时换场景不播转场。

滤镜是 `Resources/Shaders/ScreenFx.shader`。Unity 6.0 的 UI Toolkit 没有滤镜，也不能给元素换材质，所以 `UI/Elements/FxSurface.cs` 每帧用 `Graphics.Blit` 把着色器画进一张 RenderTexture，再用一个 Image 元素显示在界面里。截取旧画面用 `ScreenCapture.CaptureScreenshotIntoRenderTexture`：在帧末截下当时的画面，下一帧原样盖在原处，看不出接缝，之后才开始打碎。着色器按 1920×1080 的界面像素计算，窗口多大效果都一样。背景图不是静止的：着色器能让画面沿中心无尽地往里坠（两份画面错开一档放大、交替淡入淡出），或者切成竖列各自往下落；还能在上面加沿亮线跑的光点和往外扩的电流圈、飘动的数据块和放射状速度线，都是程序生成的，循环不会断。潜入的井是一段视频 `Resources/Art/Transitions/dive.mp4`：`Tools/dive_video.py` 在 Blender 里用卡片、代码条、气泡和光环搭一口每 60 个单位重复一次的井，镜头 8 秒落下一个重复段，所以首尾无缝；Eevee 渲出帧后由 ffmpeg 加辉光、编码。`VideoPlayer` 在开机时就解码好、暂停待命，潜入时播放进一张 RenderTexture，再当作 FxSurface 的画面过同一套滤镜（色差、扫描线、暗角、旋转放大和揭开时边缘柔和发光的圆环）。素材在 `Resources/Art/Transitions/`：数据海隧道、电路板、光带、碎玻璃、故障画面和终端日志是图像模型生成的（原图和提示词在 [assets/ui/transitions/](../assets/ui/transitions/README.md)），噪声图（溶解用的分形噪声、雪花用的白噪声）由 `Tools/transition_textures.py` 画出，这个脚本也把原图压到黑底、存成 JPG 放进游戏，并把横向滚动的光带图做成左右能接上。`Editor/UiAssetImporter.cs` 让这些图平铺（电路板镜像平铺），噪声图不压缩。

别处也用这套效果：日期卡的日期和潜空间区域横幅的地名带红青色差（`UI/Elements/Fx.cs` 的 `SplitText`），滑入时拉开、砸下时合拢；陪伴生登记和角色资料打开时，背后的画面色差撕裂一下再平复；觉醒演出的背景沿数据海一直往下坠，带速度线和光带。

弹窗打开时内容从左下斜着甩进来，菜单项逐个滑入；背后是移动的斜条纹和飘动的数据碎片。

暂停菜单参照《P4 Revival》的菜单（`UI/Modals/GameMenu.cs`）：

- 打开菜单：一道白线横切过屏，绿色笔刷从左扫入，右边斜着滑进同伴的大特写（队伍里的同伴，没有就用最近认识的角色），菜单字一个个旋转飞入，停下时每个字都略歪。光标移到哪一项，那一项的字会跳一下。菜单底色不透明，剧情画面不会透出来。
- 进入子页面（存档、读档、手机、设置、回看）：菜单字散开飞走，镜头猛推进特写，子页面在推进途中接管画面。
- 关掉子页面：镜头从特写拉回，菜单字重新落位。

每个子页面有自己的界面和进出场动画，不管从菜单、标题、快捷栏还是快捷键打开都一样（入场和出场用 `Modal.PlayMotion`）：

- 存档 / 读档（`SaveLoadModal.cs`）：相册。左边是选中存档的大照片（场景图贴在歪斜的相纸上，配胶带）和大号日期，右边是存档卡片，选中的卡片变成白色相纸、带页面色的硬阴影、向左抽出。存档是绿色，读档是蓝色。打开时快门叶片合拢再张开，伴随闪光和快门声（存档上下合拢，读档左右合拢）；存档成功时照片再闪一次，盖上 SAVED! 印章。
- 设置（`SettingsModal.cs`）：终端里打开的配置文件 `system_prompt.cfg`。每页是一个文件标签（`audio.cfg`、`text.cfg`……），每行带行号，写成「键 = 值」：滑块是方块条，开关是 `[ ON OFF ]`，选项是 `◀ 值 ▶`，选中行有闪烁光标，说明以 `//` 注释逐字打出，底部是状态栏。打开时像 CRT 开机（一道亮线展开成画面），各行依次打出来；关闭时缩成一条线再消失。
- 回看（`BacklogModal.cs`）：聊天记录。角色台词是左侧带头像的气泡，主角的台词和选择在右侧（绿色），心声是带绿边的白气泡，旁白是居中的说明文字，系统信息是等宽小条。打开时像录像带倒带：记录快速滚落到位，扫描条划过，右上角闪 ◀◀ REWIND；关闭时快进上滑。
- 手机（`UI/Phone/`）保持原来的手机界面。
- 弹窗可以叠放（手机上开资料卡、称呼框上开确认框）：下层的弹窗照常显示，只有右下角的按键提示收起，免得和上层的提示叠在同一个角上（`GameRoot.Stacked` 给下层加 `is-under`）。

剧情对话框也换成了 P5 式的歪斜黑框：白描边、说话人颜色的硬阴影，尖角指向正在说话的立绘；名牌是斜贴的白纸条，选项是错位排列的不规则黑框，选中项翻成白底。快捷栏是一排小斜标签。打开菜单或子页面时，对话框、快捷栏和 HUD 一起淡出，确认框这类小弹窗不会。

战斗结算（`UI/Battle/BattleFx.cs` 的 `ResultsFx`）：墨色和绿色斜带横扫过屏，白色笔刷带出巨型 RESULT，DeepSeek 的立绘从右边滑进、压在面板后面（主角一个人打时换成主角的立绘，不然斜带下面会露出主角站在战场上的腿）；EXP 爆炸框数字跳涨，每个队员的经验条依次填满（头像循环胜利表情），升级时弹出 LEVEL UP! 爆炸框；掉落物卡片翻入，最后闪烁「▶ NEXT」。按确定后面板甩出画面。集成的收尾特写里，DeepSeek 的立绘装在一块向左倾 6° 的墨色画框里，人跟着画框一起倾：立绘左侧是裁掉的硬边，正好压在画框自己的边上（把人转回正的话，界面只按画框的外接矩形裁，不按斜边裁，硬边会露出来），画框后面垫一块绿色的硬阴影；背后的战场压到六成墨色，定格结束后颜色和卡片都还回来。「吃饭饭！」是 P5 式对话气泡，叠在她前面。

背景粒子在 `UI/Elements/ParticleField.cs`，每个场景在 `GameData.Scenes` 里指定一种：校门和天台是樱花，教室和学生会室是光点，自己房间是夜里的微光，潜空间和战斗是气泡加数据碎片。背景图会缓慢漂移和呼吸缩放。设置 → 辅助 →「背景动态」可以关掉粒子和漂移。

## Live2D 立绘

标题、手机资料页和剧情里的立绘都通过 `UI/Portraits/PortraitView.cs` 显示：切表情、说话人高亮和变暗、说话时动嘴。某个角色有 Live2D 模型时用模型，没有就用 `Resources/Art/Portraits/` 里的 PNG，两种可以混用。战斗里的头像和技能特写也直接用 PNG，队伍卡片的表情帧见上文的战斗界面。

**没有模型时的动态立绘。** 现在三个角色都还没有 Cubism 模型（`.moc3` 只能在 Cubism Editor 里做骨骼和变形后导出）。标题和手机资料页先用 `UI/Portraits/RiggedPortrait.cs` 让 PNG 动起来：立绘画成一张 32×48 的网格，每帧按 `GameData` 里角色的 `PortraitRig`（脖子、脸、身体左右边界、肩线、腰线、闭眼贴片位置，单位是 1024×1536 立绘的像素）弯折网格。效果有：

- 呼吸：腰线以上随呼吸抬起，上半身轻微左右晃。
- 头部：绕脖子缓慢摆动，脸在头部轮廓里朝视线方向偏移，看起来像转头；说话时会点头。
- 视线：标题上跟着鼠标，鼠标不动 2.5 秒后自己四处看。
- 头发：身体左右两侧、肩线以下的长发各自随风摆，有惯性，被点到时会甩开再荡回来。
- 眨眼：每 2 到 5.5 秒一次，偶尔连眨两下。闭眼图是 `Resources/Art/Portraits/<角色>_blink.png`，只覆盖双眼一块、边缘羽化，渐显在默认表情上；其他表情的眼睛位置不同，不眨眼。

闭眼贴片的做法：截取默认表情的脸部，用图像编辑生成同一构图的闭眼版，按图像相关性对齐（三张都无需位移），取两图差异最大的两块区域（双眼）做羽化遮罩，再按遮罩边缘的颜色差校正色调后裁出。换了立绘就要按同样步骤重做贴片，并重新量 `PortraitRig` 的坐标。

有了 Live2D 模型之后，放进 `Resources/Live2D/` 就会优先用模型，`RiggedPortrait` 不再参与。剧情里的立绘仍是静态 PNG。

**安装 SDK。** 从 [live2d.com](https://www.live2d.com/en/sdk/download/unity/) 下载 Cubism SDK for Unity 的内置管线（BiRP）版。本工程用内置渲染管线；最新的 R6 只支持 URP，用不了。下载时要同意 Live2D 的两份软件许可，然后在编辑器里用 **Assets → Import Package** 导入，位置是 `Assets/Live2D/`。Cubism Core 不允许再分发，所以 SDK 不进仓库，已写进 `.gitignore`，每台机器各自导入。`Editor/Live2D/Live2DDefine.cs` 会检查 SDK 在不在，自动开关 `SP_LIVE2D` 编译定义：没装 SDK 时工程照常编译，全部用 PNG。

**放模型。** 用 Cubism Editor 导出运行时文件（`.moc3`、`.model3.json`、贴图、`.physics3.json`、`.pose3.json`、`.exp3.json`），放到 `Assets/SystemPrompt/Resources/Live2D/<角色名>/<角色名>.model3.json`。例如 DeepSeek 放在 `Resources/Live2D/DeepSeek/DeepSeek.model3.json`，战斗形态放在 `Resources/Live2D/DeepSeek_battle/DeepSeek_battle.model3.json`。SDK 的导入器会自动生成同名 prefab，游戏运行时加载它。模型需要满足这些约定：

- 表情文件以剧本里的表情名命名：`smile.exp3.json`、`pout.exp3.json` 等，`neutral` 可以不做。没有对应文件的表情显示模型的默认样子。
- 眨眼用 model3.json 里的 `EyeBlink` 参数组。
- 口型用 `LipSync` 参数组，没有就用 `ParamMouthOpenY`。说话时开合：有配音的台词开合到配音念完，没有的按台词长度；不按声音的起伏做真正的口型同步。
- 呼吸用 `ParamBreath`，轻微摆动用 `ParamAngleX/Y/Z` 和 `ParamBodyAngleX`。参数缺了就跳过对应效果。

每个 Live2D 立绘有自己的相机，把模型渲染到一张 1024×1536 的贴图上，和 PNG 立绘一样大，界面布局不用改。Cubism 按预乘透明输出，UI Toolkit 按普通透明混合，所以相机输出先经 `Resources/Live2D/Unpremultiply.shader` 换算，否则模型轮廓会发黑。取景按 Cubism Editor 里的画布：整张画布缩放进贴图，所以画布最好也做成 2:3，人物在画布里的位置和 PNG 立绘一致。立绘不在屏幕上时，相机和模型都会停下来。

目前还没有做：模型的动作文件（`.motion3.json`）不会播放；点头和点身体仍然用界面上的头部和身体区域判定，没有用模型的 HitArea。

## 剧本

剧本只在仓库根目录的 `story/` 维护。Unity 只能导入 `Assets/` 下的文件，所以 `Editor/YarnStorySync.cs` 在打开编辑器、每次进入 Play 前和构建测试版前，把 `story/*.yarn` 复制到 `Resources/Story/Synced/`（已加入 `.gitignore`），`Prologue.yarnproject` 编译这个文件夹。也可以手动点菜单 **System Prompt → 同步剧本**。不要直接改 `Synced/` 里的副本。

剧本里的命令（`<<calendar>>`、`<<scene>>`、`<<battle>>` 等）在 `Scripts/Story/StoryCommands.cs` 注册，新增命令也加在这里。说话人决定台词的呈现方式：`旁白` 是旁白框，`系统` 是左侧弹出的系统提示，`屏幕` 显示在手机画面上，`文件` 是终端投影，主角的台词加 `#inner` 是内心独白，DeepSeek 的台词加 `#thinking` 显示在思考框里。立绘表情用行标签 `#face:表情`，可选表情写在 `story/00-prologue.yarn` 开头的注释里。角色第一次说话时自动登场，换场景时清场。`<<nickname_ask 角色>>` 在对话框的位置弹出输入框（`UI/Modals/NicknameModal.cs`），玩家给角色起的称呼写进 `$player_calls_<角色名小写>`，台词里用 `{$player_calls_deepseek}` 引用，手机资料页也显示；称呼和主角姓名共用 `GameData.NameProblem` 的校验。

`<<music 曲名>>` 把配乐换成 `Resources/Audio/BGM/` 里的一首，代替场景自己的（`GameRoot.StoryMusic`），`<<music off>>` 换回来；换场景、进战斗或进潜空间时也结束，读档时从节点开头重放，所以不用存。名字后面带 `_intro` 的同名文件是前奏，`AudioService` 先放它一遍、在它结束的采样点上接循环。

`<<cg 图ID>>` 放一张全屏过场 CG（`UI/Story/StoryFx.cs` 的 `ShowCg`，图在 `GameData.Cgs` 里登记）：图盖住背景和立绘，垫在对话框下面，后面的台词照常在上面走；`<<cg off>>` 淡出收起，换场景、进战斗或进潜空间时也会收起（`StoryScreen.Show(false)` 和 `ShowScene` 里清掉），读档和新开一局同样清掉。序章有三处：`dive`（手机显示「连接成功」后往下坠，接着换到缓存海，房间碎成方块的转场就从这张图上碎开）、`abyss_whale`（影子化成光点、光之鲸升起，留到进教学战斗，中间盖着思考强度拉到 Max 的演出）和 `council_window`（学生会室整段，留到序章结束）。每张图是一段 6 到 7 秒的片段 `Resources/Art/CG/<图ID>_motion.mp4` 加它的最后一帧 `<图ID>.png`：片段由一个 `VideoPlayer` 放进 RenderTexture，解出第一帧后停在这一帧上用 0.7 秒淡入，淡入完才开始播（深渊之鲸的影子在头两秒里就散了，边淡入边播会错过），只播一遍，播完停在最后一帧；快进剧情时不播片段，直接放定格图，两种情况下台词垫着的是同一幅画面。片段两秒内放不出第一帧就改用定格图，并在日志里记一条警告。图放出来后一直缓慢地朝主体推近（约半分钟内放大 7%，推近的中心点写在 `GameData.Cgs`），片段停住以后画面也不会死。图盖着的时候立绘照常登场、换表情，只是被挡住，对话框不再伸出指向说话人的尖角。新增一张图：原图和原片放进 `Cutscenes/`，在 `Tools/cg_clips.py` 的 `CLIPS` 和 `GameData.Cgs` 各加一行，跑一遍脚本。

战斗中的提示和台词放在 `Prologue_Battle_*` 节点，由战斗系统在对应时机调用。`<<dungeon 区域ID>>` 进入潜空间探索，探索中的教学、区域、碎片和事件放在 `Prologue_Sea_*`、`Prologue_Deep_*` 节点，节点名、地图、分区和宝箱写在 `Scripts/Dungeon/DungeonData.cs`；这些节点在探索画面的对话框里播放，不能放选项；门打开（`Prologue_Sea_Gate`）、出口出现（`Prologue_Deep_Light`）、维护进度 80%（`Prologue_Deep_Warning`）和第一次被偷袭（`*_Ambushed`）的节点改由 DeepSeek 在右上角播报，只放她的台词。它们只能用探索专用的命令（`StoryCommands.RegisterHints`），目前是 `<<mirror walk|on|off>>`（两人走到出口旁的白门前、白门变成镜子、再变回来）和 `<<reveal firewall>>`（终端的节点里用镜头交代两道防火墙解除）。

## 配音

ChatGPT、Claude、DeepSeek、影子 DeepSeek、白门后的声音、班主任和两个路人的台词有配音，在剧情对话框、战斗提示、潜空间的对话框和右上角播报里都会放。主角（玩家命名、可选男女）、旁白、系统提示和 DeepSeek 的思考框不配音。三句带玩家起的称呼（`{$player_calls_deepseek}`）的台词念不出来，只有字。

配音是 Google Cloud Text-to-Speech 生成的：

```bash
python3 game/Tools/voice_lines.py
```

脚本先给要配音、还没有编号的台词在行尾补上 Yarn 的 `#line:<编号>`，再按编号生成 `Resources/Audio/Voice/<编号>.wav`：只做缺的和改过文字或音色的（对照 `Tools/voice/lines.tsv`），剧本里删掉的台词，配音也一并删掉。`--dry-run` 只列出要做什么，`--speaker 角色 --force` 重做一个角色（换音色时用）。需要 ffmpeg：每句去掉首尾静音、统一响度（两遍 loudnorm，-18 LUFS）；影子降一点调、加短回声和比特压缩，白门后的声音削掉高低频、加一点空间。

默认模型是 Chirp 3 HD（Cloud Text-to-Speech，`cmn-CN` 正式支持），音色自然，但不能按台词控制语气。`--model gemini-3.8-flash-tts`（或更快更省的 `gemini-3.8-flash-lite-tts`；更早的 TTS 模型不收逐句的语气）改用 Gemini API 的 Gemini TTS，整批重做：每句另带一段语气（`speech_metadata.style`），由角色的性格（脚本里的 `PERSONA`）、这句的表情（`#face`，同一场景里沿用）和小声组成，比如 DeepSeek 的 `sleepy` 是 drowsy, dragging the words。Gemini TTS 不用预置音色，用 Gemini 的「声音设计」（`POST /v1beta/voices`，按一段英文描述生成音色，返回 `voice_...` 编号和一段预览）给三位主角做的定制音色，写在脚本的 `GEMINI_VOICES` 表；音色存在 Gemini 项目里，一年没用会过期，过期后用同样的描述重新设计、换掉编号。描述里不要写具体年龄（写了未成年的年龄会被安全策略拦下）。语气提示（`PERSONA`）只写说话方式，不写音色本身。

## 存档

存档、设置和已读记录放在 `Application.persistentDataPath`：

| 文件 | 内容 |
| --- | --- |
| `saves/slot_00.json` | 快速存档（F5） |
| `saves/slot_01.json` – `slot_12.json` | 普通存档位 |
| `settings.json` | 设置 |
| `system.json` | 已读台词，用于「跳过未读文字」 |

存档是检查点：每进入一个 Yarn 节点，就记录一次节点名、游戏状态和 Yarn 变量，存档写入的是最近一次检查点，读档时从那个节点的开头重新播放。所以存档界面会提示「从本节开头继续」。战斗中不能存档；潜空间探索中只能在信标处存档：站到信标前按 Enter（「休息·存档」），回满 HP 和 SP 后打开存档界面。信标存档除了当前的剧情状态，还记下区域、所在信标、维护进度、用过的道具和机关、打掉的噪声体、推块的位置、反射板的朝向、走过的区域和已经说过的提示（`DungeonSave`，`SaveData.dungeon`）；读档时剧情回到 `<<dungeon>>` 所在的节点，区域按这些记录摆好，人站在那座信标前，右上角提示「从信标继续」，不重播进区域的开场对白。存档卡片和预览上写「区域·层　信标」。为此剧本里每条 `<<dungeon>>` 都单独放在一个节点里（如 `Prologue_Shallows`、`Prologue_Deep`），前后的对白在别的节点。

## 还没做的

3D 校园、序章以外的潜空间区域、日程推进、Coop 剧情、礼物和装备界面都还没开始；目前只能玩序章。Tripo 绑的骨骼没有尾巴骨，绑骨时把鲸尾、垂到背后的长发和挎包分给了最近的手脚，一动就被扯开；导入时把离整条腿或手臂太远的顶点改绑到腰（Hips）或胸口（Spine2）。（便服 DeepSeek 的 Tripo 模型已经不用了，探索里她穿 VRoid 校服，尾巴有弹簧骨。）战斗服的尾巴有骨骼，探索和战斗里都会自己摆、甩。战斗服的头发没有弹簧骨，不会随动作甩，手没有手指骨，握饭勺时手掌的位置是从手腕沿前臂往前估的（`SeaFigure` 的 `SpoonInHand`）：补这两样要回到 `claude/vibrant-gauss-5cdv9b` 分支上的绑骨源文件（`process.py` 和 .blend），在 Blender 里重做再重新导出，会覆盖手工修过的权重和尾巴，所以没做；现在这版战斗服的权重是从那一版按最近表面转过来的，同样没有这两样。主角在序章里还不能觉醒，战斗服只在镜子里出现。战斗系统只实现了教学战斗用到的部分（普通攻击、技能、深度思考、防御、道具、One More、集成），数值按 [design/stats.md](../design/stats.md) 计算。
