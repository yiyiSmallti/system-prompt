# Live2D 方案

这一篇是试验方向：人物不做 3D 模型，改用 Live2D。本作的镜头比较固定，动作也比较固定，2D 骨骼动画够用，画面还能直接贴近原设定稿和服装设定图。整篇都是提案，等原型做出来再决定要不要换掉 3D 路线。

场景、界面和战斗规则不变，见[游戏系统](systems.md)；角色外观和服装以[角色设定集](characters/README.md)为准。

## 为什么试 Live2D

| | 3D 模型 | Live2D |
| --- | --- | --- |
| 画面 | 卡通渲染要调很久才接近设定图 | 直接用原画拆层，和设定图、封面一致 |
| 长发、尾巴、翼 | Spring Bone 加碰撞体，ChatGPT 到脚踝的长发和龙翼、龙尾互相穿模 | 物理只在画面平面里摆动，没有穿模问题 |
| 镜头 | 可以绕着人物任意转 | 只能看正面到四分之三侧面，左右约 ±30° |
| 动作 | 跑、跳、转身、坐下都能做 | 适合站姿上的表情和小动作；转身、走路、坐下要另画 |
| 换装 | 换服装网格，骨架和动画共用 | 每套服装是一个单独的模型，动作要按模型分别调 |
| 工作量 | 建模、绑骨、贴图、布料、卡通渲染 | 画分层原画、拆件、做变形和物理 |

序章里需要人物出镜的地方几乎都是对话：校门口和 ChatGPT 说话，教室里 Claude 转过来自我介绍，DeepSeek 抬头、拍尾巴，学生会室 ChatGPT 看着终端。战斗也是站定的回合制。这些都是 Live2D 擅长的。真正吃亏的是潜空间探索和集成演出的大运镜，下文分别处理。

## 画面方案

背景仍可以用 3D 搭，但镜头固定，人物是放在场景里的 Live2D。

- **日常场景**：每个场景有一到几个固定机位。背景是一张图，可以是 3D 场景渲染出来的，也可以直接画，前景物件（课桌、栏杆、樱花）分层做视差。人物立绘站在背景前，和 P5 对话时的立绘位置相近。
- **主角不出立绘**：剧本是第一人称，日常对话里主角不出镜，和剧本的「我」一致。主角只在战斗、潜空间探索和事件 CG 里出现。
- **事件 CG**：趴桌睡觉、坐在天台吃饭、抱膝发抖这类站姿以外的姿势，不硬改立绘，画成单独的事件 CG。CG 也拆层做成 Live2D，只动呼吸、眨眼、头发和尾巴。
- **战斗**：改成侧视。噪声体在画面左侧，我方在右侧站成一排，人物朝左转约 30°。P5 那种从队伍背后看出去的机位做不了，因为 Live2D 没有背面。技能发动时切入 P5 式的大头特写，用立绘模型放大裁切。
- **潜空间探索**：Live2D 不适合做走路和转身，探索改成横版卷轴，用 Q 版小人。Q 版小人也用 Live2D 做，只需要左右两个朝向的走、跑、待机。

## 模型清单

## 原画分层规范

原画画在一张 PSD 里，每个会动的部件单独一层，被挡住的部分要补画完整。

- **尺寸**：全身原画按角色身高统一比例，1 cm 对应 20 px（提案）：DeepSeek 约 3,000 px 高，男版主角约 3,500 px。龙角、呆毛、展开的龙翼另外留出画布。
- **角度**：正面略偏左，约 10°。四视图的正面视图是参考，但它是正面平视，要按这个角度重新画。
- **必须拆开的部件**：
  - 脸：脸型、左右眼白、虹膜、高光、上下眼睑、睫毛、眉毛、嘴（上唇、下唇、口腔、牙齿、舌头）、腮红、鼻子
  - 头发：前发、侧发、后发分别拆成多束，长发每一束再按长度切成两到三段，方便做物理
  - 身体：脖子、躯干、左右上臂、前臂、手；裙子和外套下摆按褶分片
  - 手臂差分：每只手画两到三个姿势，用部件切换，例如自然下垂、抬手、拿道具
  - 种族特征：角、翼、鳍耳、尾巴都单独成组，尾巴按节切开
  - 发光：发光线条、发梢荧光、终端亮光单独一层，在 Live2D 里设成加算混合
- **命名**：图层名用英文小写加下划线，左右用角色自身的左右，例如 `hair_back_l_01`、`arm_l_lower`、`fin_ear_r`。

四视图里不画道具，原画也一样：Claude 的书、主角的手机单独画成道具层，挂在手的部件下面。

## 参数规范

所有模型共用一套基础参数，名字用 Cubism 默认的标准参数 ID，Unity 里的眨眼、视线、口型组件才能直接认出来。

| 分类 | 参数 |
| --- | --- |
| 头 | `ParamAngleX`、`ParamAngleY`、`ParamAngleZ` |
| 眼 | `ParamEyeLOpen`、`ParamEyeROpen`、`ParamEyeLSmile`、`ParamEyeRSmile`、`ParamEyeBallX`、`ParamEyeBallY` |
| 眉 | `ParamBrowLY`、`ParamBrowRY`、`ParamBrowLForm`、`ParamBrowRForm` |
| 嘴 | `ParamMouthForm`、`ParamMouthOpenY` |
| 脸 | `ParamCheek`（腮红） |
| 身体 | `ParamBodyAngleX`、`ParamBodyAngleY`、`ParamBodyAngleZ`、`ParamBreath` |
| 头发 | `ParamHairFront`、`ParamHairSide`、`ParamHairBack`，长发再按段加 |
| 发光 | `ParamGlow`：0 是日常，1 是战斗时发光线条和终端全亮（自定义） |

### 表情

每个 AI 角色至少做这几组表情（`exp3.json`）：平常、笑、生气、难过、惊讶、害羞、紧张、困倦。DeepSeek 另加「放空」（剧本里抬头后「眼神空了三秒」）和「完毕」（说完结论后的得意脸）；Claude 另加「若有所思」（推眼镜、不说话）。

### 动作

| 用途 | 动作 |
| --- | --- |
| 对话 | 待机（呼吸、眨眼、头发轻摆）、点头、摇头、角色专属小动作 |
| 战斗 | 待机、攻击、技能、受击、防御、倒地、掉线、胜利 |
| 专属 | ChatGPT 看手腕终端；Claude 推眼镜、写便签；DeepSeek 尾巴拍地、深度思考（闭眼，头顶对话框由 Unity 显示） |

Live2D 的动作都是在站姿上的小幅变化。攻击、技能这类大动作靠三样东西撑起来：模型本身前倾、挥手；Unity 里让整个模型位移、缩放、抖动；再叠加特效。

## 潜空间的特殊处理

### 发光

战斗服的发光线条、DeepSeek 的发梢荧光和尾巴斑点都画在单独的发光层上，用加算混合，亮度由 `ParamGlow` 控制。Unity 里再加一层 Bloom 后处理。

### 水中物理

缓存海里 DeepSeek 的头发「在水中散开，像一片发光的海藻」。物理设置不改模型，进缓存海时在 Unity 里把重力调小、加一点持续的水流（风力），头发和尾巴就会漂起来。

### 影子

影子是「一模一样的脸，但没有尾巴，没有表情。眼睛是两块冷白色的屏幕」。用 DeepSeek 战斗服模型的同一个 PSD 加几个部件：

- 尾巴整组隐藏；
- 眼睛换成「屏幕眼」部件，用参数切换；
- 乘算色调成冷灰，发光层换成冷白色；
- 不播表情，只留呼吸。

化成光点涌入 DeepSeek 胸口的演出用粒子特效做。

### 集成剪影

集成演出要把画面切成黑白剪影。Cubism 支持给每个部件设乘算色和屏幕色，运行时把整个模型的乘算色设成黑色就是剪影，不用另画。

### 觉醒形态

「深渊之鲸」是一头由光构成的巨鲸，从海面缓缓浮现、横扫全屏。它不需要表情，提案做成一个单独的大型 Live2D，只做游动和摆尾；如果原型里效果不够，就改成特效粒子加一张发光剪影。

## Unity 集成

使用 Live2D 官方的 Cubism SDK for Unity。

- **导入**：把 Cubism Editor 导出的运行时文件夹（`.moc3`、`.model3.json`、贴图、`.physics3.json`、`.motion3.json`、`.exp3.json`）拖进 `game/Assets/`，SDK 会自动生成 Prefab，动作转成 AnimationClip，可以接 Mecanim 状态机。
- **自动组件**：眨眼、呼吸、视线跟随、物理和表情都有现成组件，按标准参数 ID 自动对上。
- **口型**：本作没有配音，对话时按文字逐字显示的节奏驱动 `ParamMouthOpenY`。
- **排序**：Live2D 模型由多个网格组成，部件之间的前后顺序由 SDK 控制。和 3D 背景、前景物件混用时，模型整体放在一个排序层上。
- **界面里的模型**：技能特写和 Coop 卡里的人物用 Render Texture 渲染后贴到界面上。

剧本需要新增几条命令，和现有命令一样写在 [00-prologue.yarn](../story/00-prologue.yarn) 开头的注释里（提案）：

| 命令 | 作用 |
| --- | --- |
| `<<show 角色 服装 位置>>` | 显示立绘，位置是 `left`、`center`、`right` |
| `<<hide 角色>>` | 隐藏立绘 |
| `<<expression 角色 表情ID>>` | 切换表情 |
| `<<motion 角色 动作ID>>` | 播放一次动作，例如 `<<motion DeepSeek tail_slap>>` |
| `<<cg CG_ID>>` | 显示事件 CG，`<<cg off>>` 关闭 |

## 文件与目录

| 位置 | 内容 |
| --- | --- |
| `art/live2d/<角色>/<服装>/` | 分层原画 `.psd`、Cubism 工程 `.cmo3`、动画工程 `.can3` |
| `art/live2d/cg/` | 事件 CG 的原画和工程 |
| `game/Assets/Live2D/<角色>/<服装>/` | 导出的运行时文件 |

`.cmo3`、`.can3` 和 `.moc3` 是二进制，走 Git LFS，规则已加进 [.gitattributes](../.gitattributes)。`.model3.json`、`.physics3.json`、`.motion3.json`、`.exp3.json` 是文本，保留为普通 Git 文件。

## 授权

- **Cubism Editor**：FREE 版限制很紧：只能用一张最大 2048 px 的贴图，变形器最多 30 个、部件最多 50 个，超出限制就无法保存。本作的长发、尾巴和翼部件很多，需要 PRO 版。个人和年销售额低于 1,000 万日元的小规模事业者可以用 FREE 版或 PRO 版。
- **Cubism SDK**：免费下载使用。个人和小规模事业者发布作品时不需要签发布授权、不付费。本作是非商业同人项目，属于这一类。
- **角色形象**：原设定稿的 CC BY-NC-SA 4.0 照旧适用，Live2D 模型和原画都是衍生素材，仅限非商业用途。

以上按 Live2D 官网的[版本比较](https://www.live2d.com/en/comparison/)和 SDK 授权说明整理（2026 年 10 月），条款以官网为准，发布前再核对一次。

## 风险

- **转身和走路**：Live2D 做不了背面。凡是需要人物背对镜头、走过画面的地方，要么改成 Q 版，要么画事件 CG。
- **大运镜**：P5 式的战斗运镜和集成横扫做不出 3D 的纵深，要靠 2D 演出（切入特写、速度线、剪影）补。
- **模型数量**：每套服装一个模型，AI 角色 12 个，加主角 4 个、Q 版 7 个，还有事件 CG。头部可以做成模板，换装时复制工程再替换身体，节省脸部的工作量。
- **长发**：ChatGPT 的头发到脚踝，全身模型里头发会占掉很大一块画布和大量部件，要先做原型确认效果。

## 原型

先做一个模型验证整条路线：DeepSeek 春秋校服。

1. 按分层规范画 PSD，在 Cubism Editor 里做基础参数、鳍耳、尾巴摆动和拍地、兜帽切换、呆毛物理。
2. 导入 Unity，搭 2年C班的一个固定机位，跑一段序章对话：抬头、自我介绍、拍尾巴。
3. 把同一个模型朝左转，放进侧视战斗场景，试待机、攻击、受击三个动作，看能不能撑住战斗画面。
4. 切到缓存海，试低重力的水中物理和发光层。

这四步都满意，再按[模型清单](#模型清单)排后面的模型；否则回到 3D 路线，或者只把 Live2D 用在对话立绘上，战斗和探索仍用 3D。
